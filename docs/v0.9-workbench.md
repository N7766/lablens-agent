# v0.9：看见每次生成与修正的结果

分析计划新增“生成过程”区域。成功、校验失败和模型服务错误都会保留可查看的轨迹摘要：实际模型请求次数、请求预算、规划格式版本，以及各次请求的规则核对结果和错误。需要继续修正时，可以展开本次请求收到的反馈，查看它来自哪一次检查。完整回复与上下文仍可通过“下载规划轨迹”保存。

## 结果数量与排序分别表达

页面用三种选择解释查询结果数量：保留全部、取前 N 条、只取极值。升序和降序决定排序方向。完整 Pareto 集合必须保留全部结果；排序为准确率降序并不意味着只取准确率最高的一条。

这里展示的是计划生成使用的格式版本。执行计划编辑器继续使用原有 JSON 格式，可复核结果与离线复核流程保持原有接口。

## 成功生成仍待人工核对

只有 `needs_review` 状态会自动进入本机预览。预览展示实际条件，不会自动执行计划，也不会把有限规则匹配当作完整语义理解保证。用户核对条件、比较方向、数据来源及未处理要求后，再点击“按此计划执行”。

生成过程中的每次核对会分别显示匹配的支持条件数，以及尚未按规则核对的分句数。一次规则匹配不说明整个问题都被正确处理；未触发规则的内容仍需人工确认。

## 失败候选与有效草稿分开呈现

如果最后一次生成仍未通过校验，页面明确显示“失败候选，不是有效草稿”。若服务返回了候选执行计划，编辑器会展开供检查与手动修改；原有查询条件原样保留，页面不会自动把 `top_k=1` 改成不截断，也不会启用旧预览的执行按钮。手动编辑后，需要重新预览。

最多两次模型请求的预算不变。模型服务错误或超时会展示对应错误，不自动重试；请求次数不是成功次数。未知的新增轨迹事件不会被当作校验成功，模型文字与错误均作为普通文本显示，不执行其中的 HTML。

## 修改后旧轨迹失效

修改问题、修改计划内容或更换数据，都会清除生成过程、轨迹下载入口及旧预览。更换数据仍会清除旧计划与发送许可。较早请求返回的结果不能覆盖新的输入。导入数据的发送许可和离线合成示例与 v0.8 保持一致。

## 本轮界面检查

使用独立浏览器会话和明确模拟的生成响应，检查了两次请求后的成功预览、修正反馈、失败候选保留、模型服务错误不重试、问题/编辑器/数据变更失效，以及带 HTML 的错误文本不会创建页面元素。390 px 视口没有水平溢出。以上界面检查不调用真实模型，不计入模型评测；真实端到端结果须查看本轮评测报告。
