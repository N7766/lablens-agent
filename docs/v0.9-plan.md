# v0.9：把结果范围与排序方向分开

目标是解决Issue 26中的动作表达歧义：完整Pareto被提为maximum，即使top_k=null，编译后也会截成top1。既要允许完整集合，也要保留用户明确要求的前N条和极值。

1. 新增v2模型提案，分别指定排序指标、方向、结果范围（全部/前N条/极值）、并列处理和Pareto。拒绝范围与数量互相矛盾的参数，旧v1运行路径保留作对照；网页默认v2，底层可编辑计划和receipt格式不变。
2. 新修正反馈使用模型提案字段，针对已匹配的有限规则给出字段建议；不覆盖原提案，不静默纠正或直接执行。未知表达仍未核对，最多一次修正、供应商异常不重试。
3. 页面显示各次生成、核对失败、修正反馈和停止原因；失败提案可查看但不当成有效草稿。数据切换和编辑清除旧生成记录，成功仍自动预览，由用户核对后执行。
4. v0.8两份已知Pareto失败只作开发回归。提前冻结8道新题及新合成快照，两组同模型、同数据、相同两次请求上限，各题重复两次；比较v1与v2整体协议（提示词、格式和反馈），不能将差异单独归因某个字段。保留首轮、最终、费用与全部失败。新增题包含全量、筛选、前N条、极值、空集与token单位。
5. 完整工程回归、历史receipt、浏览器和安装包验证；推送后检查Python3.11/3.13 CI，发布源码、原始评测和版本包，更新个人主页及问题记录。通用语义验证Issue 10继续开放。
