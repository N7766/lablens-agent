# v0.12 失败处理与展示收尾

2026-10-28。v0.12.0 已完成本地简历作品的主要闭环。本次收尾补齐失败结果展示与显式新尝试，不修改 Java 任务协议、数据库模型、RAG 排序或模型提示词。

## 具体问题与改进

失败任务通常没有 `result`，页面原先提前返回，因此隐藏了后端实际保存的调用用量、安全错误详情和任务标识。现在无论是否有结果，都能查看当前任务记录。未知值仍显示为 `null`，并解释其不等于零；当前用量与缓存历史用量保持分离。

旧页面再次提交相同问题会按同一个幂等键复用原失败，这是正确的后端幂等行为，但缺少显式新尝试入口。现在失败任务提供“准备新任务重试”：填回问题、检索策略和回答方式，清除旧意图与模型发送许可，不发送请求。用户再次提交时创建新键，新任务使用当前资料版本，旧失败和旧快照保留。

重试按钮和历史任务选择均检查当前工作区及页面修订，防止迟到事件影响另一个项目。提交进行中不能改写当前意图。不确定的 POST 失败仍用原键手动重放，避免网络异常产生重复任务。

## 复现

```sh
pytest -q
node --test services/workspace/tests/workspace-ui.test.cjs
# 准备真实MySQL、Redis并设置数据库环境变量后：
LABLENS_INTEGRATION_TESTS=true mvn -f services/workspace/pom.xml verify
```

浏览器验证记录的是独立测试库里的受控服务中断。它未停止个人正在使用的MySQL/Redis进程，未使用真实模型请求模拟故障。JVM的临时8083进程验证后已停止，独立数据库保留便于审阅。

## 完成度与后续条件

作为本地工程作品，项目可以收口并用于演示、技术讲解和简历材料。v0.12冻结评测中的混合检索漏检、错误拒答和首次并发失败继续保留，本轮页面修复不产生新的检索或模型效果数字。

后续投入优先顺序是新项目与独立问题集、依据新开发集开展检索/拒答对照、完整Compose与备份恢复验证。公网鉴权、生产SLA、大规模索引、MCP和长期会话记忆按真实需求另立验收，不能算作已完成能力。
