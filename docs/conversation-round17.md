# 第十七轮：显式项目记忆与可中断HTTP

**收尾第6/12轮已完成本地工程验收，剩余6轮。** 本轮实现来源绑定的共享项目记忆，并修复持续小块HTTP响应绕过分配预算、取消等待阻塞调用返回的问题。外部模型和embedding调用均为0；完整Agent演示使用本机固定响应，不构成真实LLM语义验收。候选继续以draft PR交付，未合并、未升级8081/8765主服务。

## 场景与实现

用户反复排查同一实验时，需保留“上次看过哪份原文、哪些结论仍需核对”。直接把旧回答写成长期事实，会传播错误；资料被修改后，旧记忆也可能不再适用。因此本轮采用用户明确保存、每次明确选择的工作区共享记忆，不自动记住聊天或模型结论。

MySQL V10新增记忆记录与独立修订号，保留创建者、原文ID/版本/SHA256、资料快照、摘录、备注及到期时间。工作区行锁和列表/记录双版本守卫处理并发更新，同名冲突不会覆盖。任务事务验证最多8条选择及其批准修订，连同任务与Outbox冻结快照；Python在执行开始再次校验同一工作区、来源和到期。上下文中的记忆是未验证线索，计入原有预算，不能绕过检索和逐条证据检查。[完整契约](workspace-memory.md)说明100条上限、64 KiB限制和删除的历史保留边界。

传输改为同步请求线程内的 `asyncio.Runner + HTTPX AsyncClient`。阶段超时检测连接/读写停顿，monotonic截止控制整次调用；取消会打断本地在途HTTP，但等待连接、root/child执行栈清理完成后才确认停止。没有自动重试，不把断开连接推断为供应商停止计费。[超时修复说明](evaluations/conversation-round17/timeout-repair.md)保留原始事件与OS DNS限制。

## 本轮难题与修复

- **取消后用量误记。** 原阻塞传输不会立即抛出取消；新传输暴露了异常分支遗漏。本次未完整收到usage时必须保留未知，不能把先前已知token当总量；已完整收到的usage则继续保留。
- **清理再次被打断。** deadline和取消可能先后到达；已取消订阅的回调也可能迟到。把清理置于定时器/订阅作用域外，事件循环再次检查active标记，门控关闭测试保证确认停止之前连接已清理。
- **跨语言来源摘要不一致。** Jackson控制字符转义使用大写hex，Python使用小写，导致等价JSON哈希不同。固定小写转义并用中文、emoji和控制字符跨语言样例验证；不是削弱来源校验。
- **旧任务兼容性。** 首次全量Java验证发现新增空列表与旧构造函数的null不等价；保留初次失败日志，统一未选择记忆的规范形式后全套通过，原请求JSON不增加无意义字段。
- **历史评测拦截失效风险。** 老工具拦截全局`httpx.post`；新客户端若不同步迁移，会绕过次数预算与审计。相关Round10/13/14调用钩子一起迁移并回归，未重跑历史付费题。
- **过期检查竞态。** API和Agent重复构造请求时，时间跨过到期点可能变成500。结构/来源校验与执行前到期校验分开，排队后失效以明确422及零模型调用结束。

两位未负责相应模块实现的AI代理交叉检查UI、后端与验证脚本，结果与范围见[UI/接口审查](evaluations/conversation-round17/review-memory-ui.md)、[后端审查](evaluations/conversation-round17/review-backend.md)。这不是独立人工出题或模型质量评测。
