# v0.8：用自己的实验数据规划、核对与复核

“分析计划”现在有独立的数据选择区。可以继续使用内置 DPO 快照，也可以上传实验 JSON 数组或包含 `runs`、`notes` 的对象。导入、预览、按计划执行和离线复核都在本机处理，不调用模型。“条件查询”与“分析计划”分别保存当前页面内的数据选择，不会自动相互切换；刷新页面后恢复内置数据。

## 数据选择与发送许可

上传后，页面调用 `POST /api/plan/context` 验证数据，显示实验与说明条数、长度单位、合成数据标记、比较口径、快照标识，以及准备发送给模型的数据内容大小。来源标签只是文本，不会读取其指向的本地文件或网络地址；合成数据明确标为演示数据。

导入数据不会自动发送给模型。需要先勾选“允许将当前数据中的实验记录、说明和来源标签发送给已配置的模型服务”，再点击“生成计划”。这一许可只绑定当前快照；生成请求同时携带当前数据、问题和已确认的快照标识。更换数据后复选框恢复未勾选，旧许可不能用于新快照。内置数据不需要这一导入许可。

模型数据内容上限为 128 KiB。超过上限时，页面禁用真实生成，但有效数据仍可用于手动计划的本机预览与执行。2 MB 是文件读取上限，两者不是同一个限制。上传无效文件后，不会悄悄沿用先前数据执行计划；须重新选择有效文件或恢复内置数据。

这项勾选是发送前的界面确认，不是数据真实性、授权来源或模型服务隐私条款的认证。真实生成仍使用已配置的模型服务，并受原有最多两次模型请求的共同预算约束。

## 计划与快照始终一起传递

生成、预览和执行均携带同一份已选数据。更换数据立即清除旧计划、轨迹、预览、结果和发送许可；此失效动作发生在读取文件前。旧文件检查或旧模型请求稍后返回，也不会覆盖新选择。

修改问题或计划编辑器同样会使预览失效，并忽略尚未返回的旧草稿。用户可以继续编辑手动计划，只有重新预览后才可执行。勾选或撤回许可不会撤回已经发送的网络请求；生成进行期间改变许可时，页面忽略该请求返回的旧草稿。

内置固定示例和内置规则示例会先恢复内置数据，再载入问题与计划。它们不会在导入数据上误用 `run:sft` 等内置实验标识。

## 不调用模型的导入演示

1. 在“分析计划”点击“载入合成数据示例（离线）”。页面载入六条带合成标记的实验及说明，发送许可保持未勾选。
2. 示例问题为“列出完整Pareto集合；以run:sample-a为基线比较run:sample-c的正确题数差；说明长度单位与数据来源。”
3. 页面载入三个手动步骤：不截断的完整 Pareto 查询、明确实验 ID 的比较、资料说明。预览使用当前合成快照，不调用模型。
4. 核对原问题、实际参数及未核对内容，再按所列步骤执行。请求规则仍只覆盖有限句式；资料说明和比较方向并不因此自动获得完整语义验证。
5. 下载完整可复核结果，切换到“离线复核”重新计算。复核通过只说明文件内部的条件、数据与结果一致，不证明实验来自真实测量。

## 下载文件包含什么

规划轨迹与可复核结果包含本次使用的数据。若使用导入数据，文件也会包含相应实验记录、资料说明和来源标签；分享前应检查其内容。数据快照和结果保留在文件内，使复核无需依赖页面当时选择的数据。

旧的计划结果继续使用既有 receipt 格式及离线复核入口。新数据支持不改变“可重算”和“理解正确”的区别，也不会把合成示例当作项目真实模型评测。

实现入口：[`planning.js`](../lablens/static/planning.js)、[`index.html`](../lablens/static/index.html)。
