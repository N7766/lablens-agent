# v0.12 — 持久研究工作区与可测量的 RAG

本轮目标由用户明确提出：加入 JVM、RAG、MySQL、并发、Redis，并提供实际测试、评估指标与失败分析。既有 Python 实验计算、收据与报告功能保留。

## 架构和职责

- Java 21 / Spring Boot：项目、文档、异步任务 API；固定并发的工作线程；HTTP 调用 Python。
- MySQL：项目版本、文档、任务输入快照、幂等键、执行结果与时间的唯一事实来源。事务与唯一约束承担一致性。
- Redis：带 TTL 的离线摘录结果缓存和原子请求限流；不可用时降级，不能改变 MySQL 的幂等和任务状态保证。
- Python：文档切分、BM25、实际模型嵌入的 dense 检索、RRF 混合检索；摘录模式和带引用的真实生成模式分开。
- 工作区页面：导入文本/Markdown、选择项目、提交任务、查看队列/结果/来源及运行状态。

MCP 和自动长期记忆不属于这轮交付。文档数据持久化不表述为模型长期记忆；小型本地索引不表述为大规模向量数据库。

## 数据与并发合同

1. 文档修改和任务快照捕获在项目行锁下顺序执行；已经提交的任务使用不可变快照。
2. 每个项目中的幂等键唯一。同键同请求返回同一任务；同键不同内容拒绝。
3. 固定数量工作线程领取持久队列任务。运行状态有租约与拥有者条件更新；过期任务明确失败，不自动重试可能已经计费的模型请求。
4. QUEUED 任务在服务重启后继续；RUNNING 中断的处理与模型用量未知状态明确展示。
5. Redis 只加速，缓存按项目、快照、查询和模式隔离。新增/修改/删除文档改变快照，旧缓存不再命中。
6. 服务默认绑定本机。没有线上多用户身份体系；本机工作区隔离不能宣称为互联网多租户鉴权。

## API 合同

- `GET/POST /api/workspaces`
- `GET /api/workspaces/{id}/documents`
- `GET/PUT/DELETE /api/workspaces/{id}/documents/{documentId}`
- `POST /api/workspaces/{id}/tasks`，`Idempotency-Key` 必填。
- `GET /api/workspaces/{id}/tasks` 和 `GET /api/workspaces/{id}/tasks/{taskId}`
- `GET /api/system/status` 与实际运行指标。
- Python：`POST /api/rag/answer`、`GET /api/rag/status`。

任务请求：`question`、`strategy=bm25|dense|hybrid`、`mode=extractive|live`、`top_k=1..10`。Python 获得本次固定文档快照，缺少嵌入配置时明确返回不可用，不生成伪向量。

## 验收与证据

- 保留全部旧离线回归；增加切分、排序、引用、参数及模型错误边界测试。
- 实际 MySQL、Redis、JVM、Python 联调：并发请求、幂等冲突、项目隔离、版本变更、缓存命中、限流、Redis 故障降级、进程重启与持久数据恢复。
- 并发测量记录提交/端到端 p50/p95、吞吐量、错误率、完成数、排队和运行时间。注明机器、服务版本、并发数、样本数与缓存条件。
- 冻结语料和问题后比较 BM25 / dense / hybrid 的文档 Recall@5、MRR@5、引用原文一致性、无答案题行为、耗时与模型用量。
- 真实资料与本助手编写的问题分别标注；开发集/预留集不冒充独立外部评测。
- 真实生成只在小型预先选定子集运行；引用 ID 合法不等于语义忠实，人工/助手分析单列。
- 所有实测结果与已知失败写入评估文档；未执行的检查不得标通过。无高并发生产、业务收益或通用成功率声明。
