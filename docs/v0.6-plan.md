# v0.6：明确规划选项与有界修正

1. 增加平坦的规划动作格式：一个动作只能是查询、比较、资料说明或未支持。查询明确选择minimum/maximum/ascending/descending，再由代码编译排序方向和极值top-k；不能用缺失字段默默得到降序。
2. 按分号、句号、问号和换行形成原文分句；每句必须被动作关联，同一句不能同时被执行和标为未支持。新规划器最多两次模型请求，错误反馈只来自本地校验；超时不自动重试。界面展示覆盖状态与实际调用次数。
3. 旧v0.5题作为开发回归；冻结新题后比较旧单次规划、新单次规划、新两次预算规划。保留失败、原始轨迹、用量和评分范围；完成兼容性、浏览器、CI及预发布。

覆盖检查只是分句关联，不是语义证明；逗号连接的多个要求仍可能被漏掉，模型也可能选择错误的排序意图。既有receipt继续按原数据/计划重算，不能把升级后的提示信息当成旧文件损坏。没有独立人工审核，不声称通用可靠性或生产就绪。
