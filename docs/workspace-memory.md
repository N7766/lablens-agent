# 显式项目记忆

项目记忆用于保存成员明确摘录的资料线索，方便下一次 Agent 提问继续排查。它不等同于模型事实库，也不会自动记录聊天内容。工作区成员都能读取，编辑者和所有者可以修改；本轮不提供私人记忆。

## 使用

1. 登录候选工作区，添加资料，展开“项目记忆”。填写名称、原文资料、完整匹配的摘录及可选备注、到期时间。
2. 保存只写入 MySQL，不调用模型。名称冲突需查看已有记录后明确编辑；并发变化会要求刷新，不静默覆盖。
3. 回答方式选择 Agent，手动选用最多8条记忆，核对发送许可后提交。选择变化、记忆刷新或资料版本变化都会清除旧许可。
4. 报告可展开“本次选用的项目记忆”查看版本与来源摘要。刷新页面后历史仍引用任务接收时的版本。当前记忆的更新或删除不改写历史。

## 数据与边界

- MySQL `workspace_memories` 保存 `id/key/version/created_by`、工作区作用域、资料ID与版本、文本SHA256、原文快照ID、摘录、备注和时间。`workspaces.memory_revision` 独立于资料修订号。
- 单工作区最多100条当前记录，包含已过期和来源过时的记录；删除后释放数量。不提供后台清理任务或归档记忆版本表；任务JSON快照保留已接受的版本。
- 记忆名称使用80字以内ASCII标识符；摘录最多1000、备注500个Java UTF-16单位；到期时间是带时区时间，创建/更新时必须在未来且不超过365天。浏览器按本机时区输入后转换为UTC。
- 来源资料变更/删除会令对应记忆失效，即使新文本相同而版本不同。来源的其他资料变化不使该记忆失效，但提交仍须批准新的资料修订。
- 到期在入队时用数据库时间检查，worker执行开始时再次检查。任务执行开始之后才到期，不中断已批准的这次任务；下次提交禁止使用。到期不是物理删除。
- 删除当前记忆不会清除已接收任务、会话上下文、数据库备份或来源资料。界面明确说明历史保留，不能把此操作描述为所有副本被遗忘。
- 编辑者共享修改，没有自动冲突合并、相似记忆归并、私人范围、自动摘要写回、向量记忆检索或服务端用户记忆推荐。登录是写入记忆的必要条件；显式匿名开发模式不生成虚构用户来源。

## 一致性与Agent集成

记忆写入持有工作区行锁，并检查列表修订号和更新/删除记录版本。任务提交在既有全局准入锁、工作区锁和会话锁事务内检查记忆选择；任务、Outbox事件和所选完整记忆快照一起提交。提交字段 `memory_ids` 与 `approved_memory_revision` 不传给模型；它们被服务端验证后转为不可变的 `memory_context`。

Python验证同一工作区、来源快照、资料文本SHA256、精确摘录、重复ID和大小，再在执行入口检查到期。记忆作为不可信用户数据计入已有上下文预算，不增加工具权限，也不直接进入可引用证据目录。仍须调用检索工具，从当前冻结资料构造证据并完成核验。最终复核只接收实际检索证据，不把记忆备注交给复核当依据。JVM校验结果的记忆摘要、ID、版本和来源是否与接收快照匹配。

内置提示和机械验证降低错误使用记忆的风险；本轮固定响应测试证明流程约束，没有证明真实模型在所有恶意备注下均能正确判断。

## API

所有路径前缀为 `/api/workspaces/{workspace}/memories`，使用既有会话、工作区成员权限、Origin和CSRF规则。

| 操作 | 请求 | 返回或拒绝 |
|---|---|---|
| GET 列表 | 无 | `workspace_id/revision/memories`；状态 `active/stale/expired` |
| POST 创建 | `key/document_id/document_version/quote/note/expires_at/expected_revision` | 201及新修订、记录；同名409 |
| PUT `/{id}` | 创建字段加 `expected_version` | 更新后的版本；列表或记录过时409 |
| DELETE `/{id}` | JSON `expected_revision/expected_version` | 新修订与deleted_id；历史任务不变 |
| POST task/turn | 原有字段加 `memory_ids/approved_memory_revision` | 只允许Agent；必须来源有效、未过期且批准修订一致 |

写入丢失响应后用GET核对，不自动重发；任务仍使用既有幂等键协议。任何400/409之前必须没有入队、Outbox事件或会话修订推进。
