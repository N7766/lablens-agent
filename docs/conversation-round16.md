# 第十六轮：工作区权限、服务身份与超时机制排查

2026-11-08，十二轮收尾的 **第 5/12 轮**。完成账号会话、工作区成员权限、旧资料归属隔离和跨服务身份的本地工程验证；真实 Java→Python 身份矩阵 **53/53 通过**。本轮模型与 embedding 调用均为 **0**。同时确认了在途 HTTP 响应可能超过 Agent 总预算、延迟取消确认的机制，保留修复前证据，**本轮没有修复这一运行时限制**。

## 实现与业务边界

登录默认开启，没有公开注册。管理员通过独立配置首次建立，已有密码不被启动配置覆盖；后续由管理员创建账号。密码使用 BCrypt cost 12；会话为32字节随机令牌，MySQL只保存令牌的 SHA-256 摘要，默认绝对有效期8小时。退出删除会话；登录按真实客户端IP在MySQL中限制每分钟20次尝试，成功登录也计入。Cookie使用 HttpOnly、SameSite=Strict，浏览器写操作还必须具有匹配配置的 Origin 和会话绑定 CSRF 令牌。

新工作区与所有者在同一事务内创建。列表按成员过滤，管理员没有默认读取他人工作区的权限。OWNER管理成员；EDITOR可修改资料、提交与取消任务、导入和建索引；VIEWER仅可读。所有者不可移除或降级。旧、新工作区接口统一经过鉴权，UUID不再构成访问许可；系统诊断与指标限管理员读取。[配置、接口与权限矩阵](workspace-auth.md)。

V9迁移没有给历史工作区自动添加成员。旧记录保持无主隔离，由管理员明确选择账号接管；同一行锁内检查工作区仍无成员后才建立OWNER，不能接管已有所有者的工作区。本地开发模式须明确关闭鉴权，并限制为loopback绑定和客户端；Compose采用开启鉴权的独立服务配置。以上是本地候选验证，不是公网部署批准。

Java→Python的任务执行、取消和索引代理，以及Agent→检索工具，使用独立服务密钥。Python全部旧、新API执行同一身份检查，缺失、错误或重复身份在进入业务前拒绝。服务密钥不发送给浏览器、模型或报告；用户Cookie也不转发到worker。登录权限不能代替资料版本审批，模型调用仍需原有准确revision许可。

共享成员使用同一工作区的MySQL队列容量和既有全局准入，不按登录人重置额度。真实数据库测试中，两个成员共用配置为2的工作区任务额度，第三个新任务被拒绝。**这不是分布式token/费用硬预算，也没有增加跨worker执行配额。**

## 撤权与页面一致性

本轮契约是**请求开始时授权**：撤权提交后才进行ACL检查的新请求被拒绝；此前通过检查的在途操作、已受理任务和导入仍可继续。撤权不会撤回已经读取的资料，不会自动取消已受理模型消费，不能写成事务内即时中断。成员管理本身在工作区锁内再次验证OWNER。[代码复查记录](evaluations/conversation-round16/review.md)保留这一时序和取舍。

前端增加登录、退出和所有者成员管理，按角色显示可用动作。多标签页共享Cookie曾可能让旧页面继续保留前一身份的项目内容：现在已认证响应带账号ID，前端检查响应身份、403/404及跨标签页身份变化，立即隐藏并清理旧状态。异步旧请求返回后也再次核对身份，防止旧报告写回页面。Node测试使用延迟完成的真实前端请求逻辑验证这个竞态，不将模拟DOM测试说成浏览器端到端验收。

## 超时诊断：确认机制，保留历史未知

第十五轮真实Agent第一次模型决策用时25.374秒，随后检索14.931毫秒，命中包含SFT基线的原文。第二次模型调用获分配约34.598秒，并在约35.045秒后ReadTimeout；这来自总预算剩余54.598秒减去20秒复核预留，不是80秒总预算已经用完。原任务仍为失败、无报告，第二次用量未知；没有重新调用或改变评分。

本轮用本地HTTP服务分别控制响应头、首块和后续分块，发现同一个ReadTimeout既可能发生在响应头前，也可能发生在响应体途中。当前 `response_received=false` 只说明HTTPX没有交付完整响应对象，不能据此判断供应商未受理或未发首字节。

| 受控场景 | 配置与实测 | 可以确认的结论 |
|---|---|---|
| 现有HTTPModel持续收小块 | 分配200ms，**615.227ms**后正常返回 | read timeout限制连续读取等待，不是绝对总截止时间 |
| 现有Agent持续收小块 | 总预算1s，**1615.963ms**后 `agent_timeout` | 在途调用返回后才执行总预算检查；没有继续发工具 |
| 在途协作取消 | **103.434ms**发取消，当时 `stopped=false`；**1608.643ms**后结束 | 取消确认等待阻塞HTTP结束，不代表立即中断供应商 |

这些是一次合成本地连接的工程观测，不能作为DeepInfra延迟、TTFT或生产容量。完整事件和初次失败均保留在[诊断报告](evaluations/conversation-round16/timeout-diagnosis.md)：首次探针有6个HTTP场景完成、2个Agent场景因新身份要求在发送前阻断；补入固定合成身份后在新目录跑v2，原件未覆盖。新观察没有补写旧模型日志，也没有成为生产客户端的流式遥测。
