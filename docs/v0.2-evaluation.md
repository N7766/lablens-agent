## 设计与复现

- 数据：同一份11条真实 DPO 摘要、6条方法说明。直接回答一次获得全部原始数据；Agent通过三个只读工具读取数据、计算差异、检索说明。
- 题目：[32题数据集](../evaluation/benchmark.json)，8题开发、24题保留，按问题族划分。保留题含新的有序比较、排序、多条件筛选、缺失元数据和操作边界；与开发题仍有概念重叠，只是项目内保留集，不是独立外部数据集。
- 提前固定[评分规则](../evaluation/rubric.md)。两种方案使用同一模型、temperature=0、max_tokens=1800、相同输出结构；直接回答1次请求，无修正反馈；Agent最多8次模型、12次工具调用。
- 保留运行使用冻结提交 `03915de`。manifest在请求前记录代码、数据、提示词、rubric哈希和模型设置；后端具体模型修订号未由供应商暴露。发布时另修正通用导入的非默认单位工具描述并增加离线测试，没有根据保留题答案调提示词或重跑挑选成绩。
- `manual_*` 保持空值。每题的事实性、引用支持和任务判断记录在 `assistant-review.json`；无最终答案的事实性/引用项记null、任务项记false。未报告自动工具调用率为任务成功率。

```bash
uv sync --locked --extra dev
uv run python scripts/evaluate.py --limit 8 --workers 4
uv run python scripts/evaluate.py --cases evaluation/benchmark.json --split holdout --limit 24 --strategy both --workers 4
uv run python scripts/audit_traces.py reports/eval-替换为目录
```

复跑需要本地模型密钥并产生费用，不能保证复现同一输出。完整轨迹：[保留题48次运行、manifest、用量与审核](evaluations/v0.2/holdout/)；[最终开发8题](evaluations/v0.2/dev-final/)；[开发初版失败及源代码快照](evaluations/v0.2/dev-before/)。

- Agent 的 selection 只比较最优 DPO 与 SFT，没有找到真正最短的 run:dpo-02；数值正确但没有完成问题。

## 开发集与数值校验前后

开发初版和最终版均完整运行8题，各有7题形成有效最终输出，助手任务评分均为6/8。最终版修复了 speed 的耗尽预算，但 units 出现重复无效JSON，test_set 出现自然语言前后矛盾。固定的数值校验无法替代语义审核。

| --- | ---: | ---: | ---: | ---: |

这些运行同时包含提示词、证据元数据和校验逻辑变化，且非重复随机对照，费用差不能归因于单一校验功能。初版 speed 在8次模型调用后耗尽预算；最终增加连续相同无效答案提前停止，并保留回归测试。数值误写、单位、方向、未读来源、正确舍入等离线测试详见 tests/test_evidence_import.py。

本轮共64个真实方案/题次（开发8+8、保留24×2），已报告费用合计 **$0.06298101**，另有两次超时用量未知。此前v0.1两轮三题联调已报告$0.00457533，另有一次失败请求用量未知；两轮费用没有混成完整账单。

## 仍然存在的边界

68项离线测试通过，只能说明已测工程路径。数值校验仅覆盖结构化字段，不能检查所有自然语言、中文数字或limitations中的推断。没有独立人工复核、多次重复评测、第二个真实项目或公网生产验证。当前交付是可复现、可检查的研究原型，已知失败值得在后续新版本中修复后重新设立保留集。
