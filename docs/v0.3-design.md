# v0.3：回答契约与对照设计

## 五步交付

计划见 [v0.3-plan.md](v0.3-plan.md)，真实结果见 [v0.3-evaluation.md](v0.3-evaluation.md)。

1. Agent通过`submit_answer`提交结构化最终答案，同时兼容普通JSON返回。提交仍需经过证据校验，不能跳过读取步骤。重复无效提交会提前停止。直接回答使用`response_format=json_schema`，运行时仍校验实际输出。[DeepInfra结构化输出文档](https://docs.deepinfra.com/chat/structured-outputs)介绍了此协议；接口接受不代表语义正确。
2. 请求schema要求`limitations=[]`，模型只能选择已读`limitation_ids`；服务端复制说明原文，未选择时展示固定的产品边界。不能在局限栏自由编造“原项目没有检验”等说法。claims中的自由文字仍可能错误，这不是完整的事实验证器。
3. `query_runs`确定性计算复合条件、严格改进、排序、边界并列及Pareto集合（准确率最大、词数最小）。`selection`核对已读query_id、完整ID列表及顺序。该检查保证返回集合没有被模型删改，不能证明模型的查询参数准确理解了用户意图。多个查询时结构化selection展示一组结果，其他组仍需在claims中说明。不兼容项目/切分/单位拒绝混排。
4. `describe_data`明确当前字段、缺失元数据、只读能力与全部方法说明。缺少随机种子、GPU或费用只能指当前快照，不能推断原训练没有记录。
5. 显式动作命令使用共享的只读规则提前返回，不调用模型；它是有限的句首规则，不是通用语义分类器。分析性问题如“为什么不能上传”仍由模型解释。所有方案共享规则，评测把规则命中与真实模型结果分开。

## 更强的对照

单次直接回答仍保留；另增加`direct_repair`，最多8次调用，和Agent使用同一最终来源/数值/局限校验。直接修正版会收到确定性数值反馈，因此属于有验证器辅助的全上下文方案，不能称作纯模型无工具计算。其初始提示只含原始数据与说明，不含预计算全部答案。

Agent最多8次模型、12次工具调用，工具计数包含submit_answer。直接修正版和Agent预算上限相同，实际调用次数可能不同；Agent使用函数提交、直接方案使用JSON Schema，因此传输方式仍有差异。三组均为同模型、相同原始资料、temperature=0、max_tokens=2600。各重复两次只能初步观察波动，不能证明统计显著。

旧版所有失败题已转为开发回归集，新12题仅是同项目内的新组合，概念仍有重叠。没有跨项目泛化或独立人工评审。

## 开发回归中的追加修正

首次回归发现：模型引用query_id解释筛选阈值和匹配数量时，旧数字规则仍要求run measurement，导致合法说明无法通过。新规则允许查询专属claim重复已读参数与匹配数量；实验指标仍需measurements。它只核对数字存在于参数/计数中，不能证明数字在自然语言里扮演正确角色。返回的集合与顺序另由selection核对。

提交答案的文字中有时出现重复转义中文。校验器只规范CJK Unicode转义用于展示，不改数值或任意转义；原始provider消息继续保留。两项修正均来自旧回归题，在新保留题执行前完成。
