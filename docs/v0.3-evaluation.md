## 评测设计

旧题仅作开发回归。新题冻结在`evaluation/benchmark-v0.3.json`，三组共72次运行。每组有2次共享规则命中，零模型调用，**不计模型任务分母**；每组实际22次模型任务（11题各两次）。这些是同一11条实验快照的新组合，与旧题概念重叠，不是外部独立测试集。重复两次只能观察初步波动。

- Agent：最多8次模型、12次工具调用，含submit_answer，查询和计算工具按需返回证据。
- direct：初始给全部原始记录与说明，最多1次模型调用。
- direct_repair：初始上下文同direct，最多8次，收到同一校验器的错误和确定性期望数值；这是**验证器辅助的全上下文方案**，不是无辅助的纯模型计算。

三组相同模型、原始资料与最终字段校验；Agent函数提交、直接方案JSON Schema的传输差异仍存在。预算上限相同不代表实际用量相同。Agent额外核对selection与工具查询结果一致，但未验证查询参数是否准确表达用户问题。阈值数字检查也不能证明其语义角色正确。

运行器每组任务混排、workers=4；早期与workers=2的开发回归重叠。时间包含供应商排队与网络影响，只是本次观测，不能作为严格性能排名。失败请求如果没有usage，费用未知，不用零补齐。费用使用响应中的estimated_cost，不是账单核对。

## 已知边界与复现

新增工具减少了部分手算和集合错误，但结构化检查不能保证自然语言推理正确。新题中可见：Agent并列题第二次调用返回了全体记录，最终文字却称438题最少；两类直接方案可能列出被支配的Pareto成员。数值本身正确也不能证明成员选择正确。这些均计任务失败，不以协议completed替代。

固定数值容差仍为fraction 0.00005、计数精确、其他0.005。例如长度降幅0.485与真实0.487805差约0.002805，在预先设定容差内，因此接受；这不表示精确到小数点后三位。集合漏项与错误排序不因数值容差而放行。
