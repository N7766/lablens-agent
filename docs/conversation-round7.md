# LabLens 第七轮：比较覆盖、澄清与复核优化

2026-10-31。本轮实现和一次真实模型回归已完成，**答案质量仍未通过验收**。[PR #48](https://github.com/N7766/lablens-agent/pull/48) 保持草稿，主服务保留上一版。候选 `619c051` 的真实结果与之后的离线修复分别保存。

## 本轮解决什么

- 用户更正对象后，原报告会只给新值、漏掉明确要求的“哪些变了、哪些保留”。现在对当前问题中的有限显式列表补充中性比较槽，统一交给原复核调用；总计仍最多八条。
- 用户已要求“给出能确认的结论和缺失证据”时，模型有时仍要求先补资料。现在完成检索后限制此类不必要澄清，保留对象歧义与用户要求先确认范围的路径。它是有限规则，不是通用语义判断器。
- 复核响应用短 ID 绑定服务器保留的命题，拒绝缺失、重复、陌生 ID 或伪造 statement；随后仍核对来源、数值和范围。受控等价八行示例的构造响应从 2,428 降为 1,976 字节（18.6%），但请求从 19,953 增为 20,137 字节。没有据此宣称真实 token、时延或质量改善。
- Java 接受 v8 工具轨迹与澄清策略；超时文案改为“请求或执行时限”，不再把仍有剩余预算的阶段超时一律写成总预算耗尽。

## 实际难题、确认项与未解决项

1. **覆盖检查误拒绝已有结论。** Cedar 八行草稿已含“通过/未通过 C-21 验收”，有限匹配没识别中间的试验 ID，误补两槽并在 review 前停止；不是检索失败或总预算耗尽。Harbor 没识别“也不通过”，多补一槽。封存后保留原失败，只做原稿离线回放修复。独立复审又发现 P99 指标误当编号、另一对象问句影响已答对象的问题，后续修复与测试独立记录在[封存后修复](post-evaluation-round7.md)，不能套用本轮模型分数。
2. **引用存在不等于支持结论。** Harbor 的 Sable 标题下出现 Quill 的原因及引文；Kite 用告警卡片支持额外添加的配置数值。短 ID、引文原文匹配和数值检查均未阻止这类语义错误，尚未解决。
3. **比较槽存在不等于比较正确。** Alder 已检索到两个范围的资料，仍以“不同对象”错误拒答三个变更/保留问题。旧答案只作为对话上下文、来源作为事实依据的边界需要更清楚；当前不能把某条提示词定为唯一根因。
4. **评测器本身也会误报。** 执行前复审查出五类标注/身份/用量校验缺陷，逐项修复并冻结；真实 raw、原 gold、首次失败和内部 AI 的评分分歧均保留。[过程与排除项](evaluations/conversation-round7/execution-notes.md)。

刷新后可以重新选择会话、查看同一报告，合理澄清和失败轨迹也可回看；[浏览器记录](evaluations/conversation-round7/browser-check.md)不代替语义评分。隔离 QA 已安全关闭，五张表哈希与记录数保持，主服务健康与进程身份保持；资料、任务、会话和原始证据保留。
