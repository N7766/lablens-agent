# LabLens 第十轮：复核协议清理与有界失败诊断

2026-10-31。本轮完成提示契约修复、离线回归和预先限定的四次真实直接复核。**四次请求均超时，未收到 HTTP 响应，也未交付报告。** 代码中互相冲突的输出要求已清理，但真实模型复核验收仍未通过；主服务未升级。

## 本轮解决的工程问题

上一轮 Cedar / Harbor 在收到 HTTP 200 后未交付报告，但当时未保存失败正文，无法再确定失败落在 JSON、ID 分区还是引文校验。检查发现，同一个 system 提示同时要求普通单列表报告、固定 ID 全量报告、保留/替换双列表报告。它是可直接确认的提示缺陷，尚不能认定为历史失败根因。

本轮把共用证据规则与各路径的输出格式分开：scoped 稀疏复核只描述双列表协议；普通生成和非作用域复核的提示保持原字节及 SHA-256。共同的事实、因果、配置/历史、算术和适用范围规则保留，响应 schema、ID 分区恢复器与最终校验没有放宽。缺行、重复、重叠、错误来源不会被自动补齐或默认为通过。[协议检查与修复依据](evaluations/conversation-round10/protocol-review.md)

## 来源重建与实验约束

从封存的原始 tool args、搜索结果和 pinned state 重建两份初稿，使用固定历史 commit 的源码在隔离进程执行，并逐文件核对 SHA-256。重建请求体分别为 29,533 和 28,064 bytes，与旧 trace 计数相同；没有用最终报告冒充模型原始提交。由于旧 HTTP 请求全文未留存，字节数相等不能被表述为原始 wire 内容逐字恢复。[重建过程及限制](evaluations/conversation-round10/reconstruction.md)

实验事先限定为 baseline 和 repaired 两阶段，每阶段两次直接 review，共最多四次；固定同一 DeepInfra 模型、temperature=0、max_tokens=2600、资料和初稿。Cedar / Harbor 分别沿用 39,968.432 / 35,098.544 ms 的原复核时长。持久一次性 claim 防止重复阶段，输入、源码、协议和语义清单绑定候选提交，原始产物先封存再阅读。没有新检索、embedding、Agent 决策或数据库任务。[运行前协议](evaluations/conversation-round10/protocol.md)

## 难题、处理方式和未解决项

- **旧响应丢失后如何继续取证。** 保留旧证据缺口，通过原源码和原工具参数重建可核验输入；新请求完整记录发送意图、状态、用量与错误。此次没有收到响应，因此没有伪造 response 文件，也没有用新 timeout 回填旧 HTTP 200 失败原因。
- **异常中断不能留下虚假的零用量。** 运行器在模型调用前补齐阶段身份、环境检查、telemetry 接口与中断用量处理，失败后仍封存记录并禁止自动恢复。[执行记录](evaluations/conversation-round10/execution-notes.md)
- **timeout 参数不是硬实时的外层耗时上界。** 本次观测总耗时比复核 allowance 多约 0.57–0.87 秒；没有提高传入请求 timeout，仍需如实区分 HTTP 阶段超时与外层 wall-clock。直接 review 也不代表整条 Agent 在 75 秒内完成。
- **提示修复不能替代传输根因分析。** 本轮只确认四次客户端请求超时，不能据此归因于供应商故障、模型负载或提示长度。没有返回正文，无法检验修复后真实输出是否满足分区及语义要求。

Round 9 原始记录、评分和失败均保持原样。本轮没有重跑其十轮评测，也没有补造独立人工新题、生产流量或上线事故经历。
