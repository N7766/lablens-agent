## 条件查询：不调用模型

1. 打开工作台，使用内置数据或导入实验JSON数组。也支持`{"runs":[...],"notes":[...]}`；字段见[导入格式](import-format.md)。每份bundle最多100条记录、20条说明，浏览器文件上限2MB。混合不兼容项目/切分/单位的记录可以检查，但不能混排查询。
2. 输入准确率边界、正确数、长度上限，或严格优于指定基线；选择排序、top-k、并列、Pareto。
3. 预览实际条件，再执行。参数或数据变更会使预览失效。top-k指排序后的前k条，启用并列时扩展第k条所在边界，不是前k个不同名次。Pareto在筛选后的集合中计算。
4. 下载可复核结果，到“离线复核”选择同一文件。也可用CLI离线重算。

导入内容只用于本次本机请求，不写入内置数据或持久化会话，不自动调用模型。切换到Agent页时会明确使用内置DPO快照。CLI的`ask --data-dir`可主动将自定义摘要提供给配置的模型供应商。

## Agent查询结果

模型仍自主选工具和参数。使用query_runs后，最终显示由服务端生成的所有查询表格，每张表包含实际参数、完整记录、原始数值和snapshot ID；模型自行生成的查询文字只保留在原始事件中，不作为最终结论。提交仍需匹配查询selection和已读局限说明。

这避免了“工具返回437，模型写成438”或返回集合被自由文字删改的问题。**无法保证模型选用的条件正确理解自然语言**；界面会标注条件未确认。复杂混合请求还可能缺少额外解释或比较，此时不能把准确的查询表格等同于整题已完成。非查询回答继续使用原来的证据校验与模型解释流程。

## 可复核结果

receipt包含版本、标准化数据、参数、结果、快照ID及内容SHA-256。复核先检查内容摘要，再用封装的数据重算完整结果。更改结果并重新计算外层hash仍会被重算检查识别。

哈希不是签名。如果有人同时替换数据、结果和hash，复核可能通过；它证明内部一致性，不证明来源真实、请求者身份或用户意图。模型调用轨迹与receipt是两种文件，“离线复核”只接受receipt v1。

## CLI

```bash
lablens inspect
lablens inspect --data-dir /path/to/imported-data
# query.json示例：{"order_by":"correct","descending":false,"top_k":1,"include_ties":true}
lablens query --query-file query.json --output result.json
lablens verify result.json
# 自定义数据也可显式交给真实模型：
lablens ask '比较记录' --data-dir /path/to/imported-data --output trace.json
```

`query`由命令行传入明确参数，自动使用同一预览/执行校验；无模型调用。`demo`固定使用内置场景，拒绝与`--data-dir`混用。查询与复核错误通过非零退出码报告。

## API

| 路径 | 用途 |
| --- | --- |
| GET /api/dataset | 内置数据概况 |
| POST /api/dataset/inspect | 验证请求中的runs/notes |
| POST /api/query/preview | 验证参数、兼容性并生成绑定数据和条件的preview ID |
| POST /api/query/execute | 核对preview ID后返回结果与receipt |
| POST /api/receipt/verify | 不调用模型，重算receipt |

请求只含数据对象，不接受服务器文件路径。接口没有身份认证或多用户存储，继续限定本机演示；浏览器2MB限制不是生产级服务端流量配额。
