# 三分钟演示

1. 打开工作台的“条件查询”，选择“并列最少示例”，预览条件后执行：显示10、11、12三条，并说明top-k边界并列规则。
2. 下载可复核结果，切到“离线复核”导入同一文件，展示本机重算通过。修改内容后再次复核会失败。
3. 回到条件查询，导入`evaluation/fixtures/synthetic-runs.json`，说明这是合成夹具，查询不会自动发送给模型；恢复内置数据。
4. 切到Agent分析，提问“在准确率不高于95.2%的候选中，求准确率更高、输出更短的Pareto集合”。查看模型实际参数与04、10的完整表格。该调用需要本地密钥并产生费用；也可用固定离线演示展示原有SFT/DPO比较。
5. 打开[v0.4报告](v0.4-evaluation.md)，解释为什么4类查询的8/8不能代表通用能力：工具与表格承担了确定性计算，新旧评测不可直接比较，且没有独立人工审核。

## 代码讲解顺序

- `tools.py`：为什么差值、筛选、排序和Pareto交给确定性代码。
- `agent.py`与`presentation.py`：模型选择工具和参数；查询表格由代码生成，原始模型消息保留在轨迹中。
- `datasets.py`与`workbench.py`：请求内数据、快照指纹、预览失效和结果重算。
- `evidence.py`：非查询回答的数值/单位/方向/来源校验，以及自然语言仍可能出错的边界。
- `evaluation/rubric.md`：协议完成与任务完成分开；失败、未知用量和评分人身份均公开。

不要把脚本回放称为真实推理，把哈希称为数据真实性证明，或把本地原型称为生产多用户系统。
