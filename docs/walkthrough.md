# 三分钟项目演示与面试讲解

1. 打开本地工作台，运行固定离线演示：先交代它是可重复的工程回放，不是模型评测。
2. 输入“比较 SFT 与最优 DPO，说明结论边界”，运行真实模式。展开 list_runs、compare_runs 和最终 measurements，展示计算来自工具。
3. 问“能说明统计显著提升或推理更快吗”，解释为什么摘要不足以支持这些结论。
4. 展示 `tests/test_evidence_import.py`：错误数值、单位、顺序或未读来源被拒绝，并在预算内反馈修正。
5. 打开 v0.2 评测报告，比较同一份资料下直接回答与工具循环的结果、耗时及费用。主动说明小样本、单次运行和助手审核限制。

## 可以讲清楚的技术选择

- 自己实现有界循环：便于读代码理解状态、工具消息协议、错误修正和终止条件；并不意味着框架没有价值。
- 确定性工具承担运算：模型选择工具与解释资料；结构化字段由代码核对，自然语言仍可能出错。
- BM25 使用中英文词法切分：适合当前六条短说明；没有大规模语料证据，不宣称优于向量检索。
- 通用导入在边界验证：统一单位与切分，哈希用来追溯文件，不把哈希当真实性证明。
- 直接回答基线一次性获得全部摘要，Agent 按需读取且可修正：工具的收益必须和增加的时间、调用量一起看。

## HR 入口

项目首页 → 可运行演示 → 真实评测报告 → 失败轨迹与测试 → Release 和已完成 Issues。GitHub 活跃来自有内容的版本与改进记录，不使用空提交或自动刷贡献图。

正式面试前亲自运行一次，重点读 agent.py / tools.py / evidence.py，并能解释失败案例。简历草稿保持为本地文件，不替代你对项目的理解。
