# Round14 / 收尾3：历史规模、投影与游标对照

2026-11-08。三套独立新库，各 1,000 / 10,000 / 100,000 条历史；合成终态行不等于实际执行十万个 Agent 任务。生成器固定四个工作区、90%热点工作区、每8序号共享一个时间戳、稳定UUID、约4 KiB快照和2 KiB结果正文。保存实际JSON字节、表/索引分配、种子/源码/SQL流哈希；旧库与主服务不动。开始前磁盘至少5GiB空闲，生成过程中保留3GiB，不足或单规模超过240秒就停止并保留部分状态。

对照构建为上一轮 `0f732e4` 对应归档jar与本轮冻结候选，复用同一规模的数据库，不改变连接池、JVM资源或资料。保留旧无参列表契约；新摘要视图按100条比较相同ID，另有UI默认25条。正文移至单任务详情是接口职责改变，不能写成相同完整响应的压缩算法。

每规模按 baseline/full → candidate/summary → candidate/summary → baseline/full 顺序（ABBA）运行，进程分别重启、5次预热后测量。每次对列表、固定详情、精确状态各做20次顺序读取，另做8客户端×10次列表闭环读取；保留所有155次（包括15次预热）的HTTP状态、耗时、字节、内容哈希、列表ID哈希和验证结果。无隐藏请求重试，不丢弃异常或慢值。所有请求必须正确、摘要ID与相同资料排序一致、详情正文完整、状态总数准确。

每个测量目录独占，失败不可覆盖。固定轮次是预先声明的重复对照，不是失败后重跑挑选；同组两个窗口均公开，不能只展示更好的一次。代码回归、sender受控实验、真实模型调用不与正式HTTP测量重叠。只有一个JVM运行，2个worker、12连接、Tomcat上限200、JVM -Xms128m/-Xmx512m。测量期间关闭dispatch，资料全为终态，无模型/embedding调用。任务状态统计和outbox统计仍为真实查询，观察器本身会贡献数据库活动。

这不是冷缓存实验：仅JVM重启，MySQL/OS缓存不清空、不重启共享MySQL。ABBA和预热缓解顺序/JIT影响，不能消除同机系统干扰。小样本p95不表示生产SLA，不以闭环请求数宣称开放流量吞吐或最大容量。

SQL证据保留EXPLAIN FORMAT=JSON与EXPLAIN ANALYZE：实际旧列表、窄投影首屏、80%深度的等投影OFFSET参考与keyset、精确状态计数和详情。OFFSET只是SQL参考，旧HTTP接口并没有深分页功能。执行计划单次耗时不是p95。优先复用现有workspace/created_at索引的隐式主键；若真实计划显示无效，再依据证据修复并保留初版结果，不能为堆索引而加重复项。

大快照重复存储和状态全表统计会被量化，但本轮不擅自引入统计计数表、异步一致性或快照迁移。分页语义是时间/ID边界，不是冻结数据库快照：新插入的更晚记录需刷新首屏，状态可以变化，删除边界记录不应使后续页失效。游标绑定工作区用于防误用，不替代鉴权；公网权限仍待后续轮次。

本轮另有独立sender与模型协议。任何局部通过不重写Round13漏发或旧模型分数。
