# Round 14 发送器调度受控诊断协议

本协议在运行前冻结。Round 13 槽位 3237 在发送前观测到 111.089 ms 迟到，超过既定 100 ms 门槛，因此未发送；旧结果继续为失败。现有材料不能确认历史迟到的根因。本轮只检验一种明确机制：同步观察工作占用发送器事件循环时可能造成漏发，把观察工作放入独立进程是否能隔离该机制。即使通过，也不自动关闭 Issue #53，不把旧结果改写为通过。

## 固定对照

- 新工具 `scripts/diagnose_arrival_scheduler.py` 独立运行，不修改、执行或重新汇总 Round 12/13 旧压测工具和封存资料。
- 顺序运行 `shared_loop`、`isolated_process`。每组固定 2/20/2 次每秒，各阶段 6 秒，共 18 秒、144 个预定槽位；两组约 36 秒，进程准备和清理另计。最多允许每阶段 8 秒，不启动长压测。
- 发送门槛保持 100 ms；迟到槽位原样记为 `unsent`，不补发，不重试。最多 32 个未完成模拟 dispatch。每次 dispatch 仅 `asyncio.sleep(0.002)`，没有 HTTP 请求、数据库、Redis、模型或业务服务调用，不能把 `dispatched` 当作业务接受任务。
- 每组在 0.2、1.2、……、17.2 秒预定执行 18 次观察。每次包含相同的 180 ms 同步等待注入、相同 32 KiB 合成 JSON 编码与追加写盘工作。同步等待是人为可控的阻塞，不是对历史观察器耗时的估计。
- `shared_loop` 在发送器所在 asyncio loop 执行这段同步观察；`isolated_process` 用独立进程执行全部观察工作及写盘。选择进程是为了隔离观察器的同步文件 I/O、JSON 编码和 Python 执行，不能据此声称隔离了操作系统调度、磁盘或所有同机资源竞争。
- 独立进程先完成 readiness 握手，再约定统一单调时钟起点；启动不计入 18 秒到达窗口。准备最多等 5 秒。结束后 join 最多 2 秒，必要时 terminate/join 1 秒、kill/join 1 秒，并记录实际退出状态；任何未确认退出均使验收失败，不留下后台进程继续实验。
- 正式对照仅运行一次，独占一个新输出目录。失败、漏发、未执行观察、未知完成状态和进程退出问题全部保留；不调高门槛、不删除目录、不换参数补跑直到成功。修复后必须另建协议版本和实验身份。

## 证据与判定

发送器按固定预定时间推进，不等待前一 dispatch 完成。请求账本在内存收集，结束后统一保存，因此两组的发送器写盘策略相同；本轮隔离的是观察器工作，不是所有可能阻塞源。

每个预定槽位保存阶段、预定时间、实际 dispatch 时间（若有）、迟到、结果和未发送原因。额外以 10 ms 心跳探测事件循环调度延迟，保存每次实际唤醒的预定/实际时间、lag 和因同次迟到跨过的 probe tick 数；不把跨过的 tick 伪造为零延迟。

每个预定观察都有最终账本行：正常完成含实际开始、结束和耗时；缺失开始或缺失完成要明确写出，不凭缺失日志推断它从未执行。原始观察开始/结束事件和合成写盘文件一并保留。观察器 duration 量到完成事件写入前，包含同步等待、编码、payload 写入及 flush 的实测耗时，不解释为纯磁盘耗时。flush 不等于 fsync，本实验不测物理磁盘持久化延迟。事件循环 lag、观察耗时、模拟 dispatch 耗时和整个进程清理时间分开报告。

运行前后核对工具、协议与测试源码 SHA-256，记录指定 source commit、Python/操作系统版本与完整非敏感参数；记录两组相同的预定槽位及观察日程。所有槽位必须各一次保留，所有 dispatch 必须明确结束，所有计划观察都必须能在账本追踪，独立进程退出必须确认。检查失败不能从报告中删除。

机制对照的预声明成功条件：共享 loop 组至少一个迟到漏发且 heartbeat 最大 lag 超过 100 ms；隔离组迟到漏发为零且 heartbeat 最大 lag 不超过 100 ms；两组观察全部完成、dispatch 无错误、全部账本与来源检查通过。若不满足，就报告未复现或隔离未满足本协议，不能只挑有利分位数。

本轮结果仅覆盖该注入、参数和环境的一次本地受控对照。即使隔离组 144 个槽位均 dispatch，也不证明原真实 HTTP 压测的漏发已解决、服务承载提高、生产可用性或模型吞吐；下一次真实流量仍需独立冻结协议与原来的门槛。
