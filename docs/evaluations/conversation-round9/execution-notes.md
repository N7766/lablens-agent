# Round 9 执行与难题记录

2026-10-31。本轮从候选分支 `528a1fe` 继续；没有改变主服务、旧问题、原 gold 或历史封存输出。

## 开发选择

1. **验收不是机制因果。** Round 8 的整体结论使用 `causal_claim`，旧因果护栏因而拒绝。新增 `rule_evaluation` 类型和逐行测量/规则要求；保留因果护栏。没有把 causal 标签一律转换成通过，也没有增加通用规则解释器。
2. **算术可复用，但证据不能借用。** 同一对象的明确计算可提供一跳数值凭证；消费行仍须自己选择完全相同的操作数片段及明确公式规则。若计算行随后会被来源、数值、对象或因果检查拒绝，就不能发凭证。额外反例发现“较大表达式的合法子式”风险，因此凭证层拒绝前后仍有运算的表达式。阈值、AND/OR、来源适用性与最终验收语义仍需单独评价。
3. **减少重复输出的机会。** 固定命题仍逐条复核；正确行可以明确列在 retained ID 列表，其余行完整替换。两组 ID 必须精确覆盖原稿，无默认保留。空证据占位、已知数量/对象问题、非目录引文与 supported causal 行不能保留。全量恢复后统一执行现有检查；超时不返回原稿。
4. **输入更长也要记录。** 新协议增加 schema、说明和审计信息。旧测试的“每行完整返回”“新请求必定更短”假设不再适用；保留原文/目录/约束无损检查，另测请求和响应字节，不能把 JSON 字节当 token 或推理时延。
5. **保留后置检查之前的响应。** 独立代码审查发现只保存 ID/hash 不够追溯后置改写。新增有界原始复核 JSON，随真实 `review_completed.output` 和结果持久化。保留行仍以原始工具提交稿为依据；审计不是额外模型调用。
