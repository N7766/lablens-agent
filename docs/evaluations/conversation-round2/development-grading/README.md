# 已曝光问题的开发者语义复核

复核者是参与本轮实现的 AI 开发者。这里不是人工独立评测，也不是新问题盲测。使用第一轮冻结的 rubric；逐项检查结论、所问比较、样本范围、当前资料来源、指代及会话状态。引用原文存在不等于结论通过。用户范围附录只记录输入意图，不能替代证据支持的实验范围说明。

详细判分、原始任务文件 SHA-256、用量及上下文证据见 [review.json](review.json)。三个执行批次分别保留：

| 批次 | 实际提交 | 完成回答 | 严格通过 | 部分回答 | 执行失败 | 前置失败后阻塞 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 首个 v3 候选，决策上限 30 秒 | 3 | 1 | 0 | 1 | 2 | 3 |
| 修正候选首轮，含 worker 启动连接失败 | 3 | 1 | 0 | 1 | 2 | 3 |
| worker 就绪后，显式触发 CedarBend 专项复测 | 3 | 3 | 2 | 1 | 0 | 0 |

修正候选的六个计划问题采用第二批次的 HarborBridge 与第三批次的 CedarBend 汇总：**2 个严格通过、2 个部分回答、1 个超时、1 个因前置失败而阻塞**。这不是一次连续执行的“六题通过率”；启动失败与显式专项复测均不能省略。

| 问题 | 语义结果 | 判定依据 |
| --- | --- | --- |
| cb1 | 部分 | 候选 62ms/248MiB 和本地合成 120 请求正确，但遗漏明确要求比较的基线 84ms；未完整说明同条件比较及生产推断边界。 |
| cb2 | 通过 | 正确继承 spruce-lab 指代；112/120 未达 118/120；延迟和内存通过不能补偿正确性；不混入回放结果。 |
| cb3 | 通过 | 三条实质结论，拒绝推荐、说明正确性证据，并明确本地合成结果不能说明生产表现。 |
| hb1 | 部分 | 两候选召回和延迟正确，区分检索与回答质量；合成属性仅在用户附录中出现，未进入证据结论。 |
| hb2 | 无法观察 | 超时，没有接受的回答，不能据此判断是否能正确澄清指代。 |
| hb3 | 未执行 | hb2 失败后阻塞，不能计为检索失败或语义通过。 |

四个已完成的可回答问题中，所需资料路径覆盖为 **4/4 题、6/6 个必需路径出现次数**；错误拒答为 **0/4**。这两个分母排除超时和未执行问题，不能作为全六题的系统成功率。已观察的 15 项事实标准通过 13 项；另外还有 hb1 的实验范围边界失败。七项事实标准因无回答或阻塞而无法观察。

四份已完成报告的耗时分别为 **31.19、65.76、53.18、70.79 秒**，中位数 59.47 秒。五个实际提交任务可见 17 次模型调用；已知生成 token 合计 54,634，但一个超时任务的 token 用量未知，因此不是完整账单总量。
