# Round17：记忆交互与演示链路交叉审查

审查对象：当前候选分支的 `memory.js`、`workspace.js`、`index.html`、`MemoryRequests` / `MemoryStore` / `WorkerResults`，以及 `round17_local_model_fixture.py` 和 `verify_workspace_memory.py`。

执行者参与了本轮 Python 记忆上下文实现，未编写本轮前端、Java 记忆存储和演示脚本。因此，本文是对这些相邻模块的交叉代码审查，不是整个记忆实现的独立评审，也不是独立人工出题或真实模型质量评测。下述 UI 结论来自源码检查；真实浏览器和整条服务链路的结果以本轮独立保存的运行记录为准。

## 交互与权限边界

- 记忆需用户手动选择，仅在 Agent 模式下进入提交请求。发送许可绑定资料版本、问题、会话状态、记忆 ID 集合和记忆修订号。改变选择、刷新记忆或更新原文会使先前许可失效；未自动附加全部记忆。
- `memory.js` 的列表、备注和摘录使用 `textContent` / 文本节点渲染，没有把成员填写的内容拼入 HTML。这里检查的是该渲染路径，不代表对全部前端进行安全审计。
- 所有者和编辑者能编辑记忆；只读成员能查看共享内容，不能提交任务或编辑。服务端仍承担最终权限检查，前端禁用按钮不被视为授权机制。
- 异步读取使用工作区 ID 与递增 epoch 双重检查，覆盖切换 A→B→A 时旧响应污染新视图的问题。变更响应不确定时只发 GET 对账，不自动重放 POST/PUT/DELETE；旧草稿保留，版本冲突需显式重新处理。
- 当前记忆更新或删除后，已接收任务仍保留当时的选择与来源。界面文字已经区分当前列表和历史任务快照。该功能属于工作区共享注释，不提供成员私有记忆或删除历史任务资料的能力。

以上源码检查未发现需要阻断本轮交付的 UI 问题。可读性小项：为 `invalid_memory_context` 增加中文终止状态，避免界面回退显示英文代码。

## Python 与 Java 的来源约束

Python 检查工作区、来源快照范围、当前冻结资料全文 SHA-256、精确摘录、唯一 ID/名称、大小和 Unicode。资料版本号的真实性由 Java 对数据库当前记录核对；Python 请求中的文档没有版本字段，不能独立证明该版本号，因此结果元数据明确记录这一职责边界。

请求模型进行不依赖当前时间的形状及来源检查；执行开始时重新检查过期时间。这样可避免首次请求解析与 Agent 内部重新构建请求之间跨越过期时刻，造成未捕获验证异常。过期上下文返回 `invalid_memory_context` / HTTP 422，保留身份和零调用用量，而不先初始化模型服务。

记忆正文只进入当前用户消息里的 `untrusted_workspace_memory`，受现有完整请求字节预算约束。它不会填充检索结果、核验集合、证据目录或工具定义；最终复核只接收实际检索来源和报告草稿，不携带记忆正文。无记忆请求保持原有提示路径。

这些检查限定了证据和工具入口，但不能证明任意真实模型都能抵抗提示注入，也不能证明成员备注的语义正确。来源摘录精确匹配只证明该文本存在，无法证明备注中的推断成立。

## 发现并处理的跨语言问题

Java / Python 对 JSON 控制字符的默认十六进制转义大小写不同，会导致同一合法记忆的上下文哈希不一致。当前 Java 已使用关闭 `WRITE_HEX_UPPER_CASE` 的共享规范化序列化器；`MemoryRequestsTest.canonicalHashMatchesPythonForControlCharactersUnicodeAndEscapes` 包含控制字符、中文、emoji 和字面转义序列的固定 Python 预期值。这一处理保留原文内容，无需删除合法原文字符。该问题的源码修复和测试用例已经复核，Java 测试执行结果应引用本轮 Java 验证记录。

## 本地演示脚本检查

已核对以下接口约定与现有实现相符：资料 PUT 成功返回 HTTP 200，并提供 `revision` 和 `version`；首轮会话任务使用会话 revision 1；成功的组合提交轨迹包含 `search_workspace` 与 `verify_and_submit_report`，确定性核验另记为 `source_validation`；最终证据复核使用包含 `retained_assessment_ids` 与 `assessments` 的 delta 协议。

本地 provider fixture 返回预先编写的响应和合成用量。它能证明模型协议适配、工具调用、来源核验、报告保存和历史读取的工程链路，不能证明模型自主推理、抗注入成功率、准确率或真实 token 消耗。脚本中“备注写 100%，报告引用原文 86%”是受控协议用例，不能据此宣称真实模型已通过对抗评测。

运行前已向主执行者提示两项限制：

1. 任务完成本身也可由数据库轮询回退触发，不能单独证明 MQ 通知被消费。若报告声称走通 MQ，应另保留本任务 outbox 确认与 inbox 接收记录；否则只表述为开启 MQ 的部署中完成任务。
2. 过期用例采用非常短的创建窗口，繁忙数据库或调度延迟可能使创建时已过期。建议延长创建窗口和观察上限，并保留实测等待时间；该建议不改变业务过期语义。
