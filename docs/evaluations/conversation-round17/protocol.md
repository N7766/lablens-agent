# Round17 / 收尾第6轮：显式记忆与可中断HTTP

基线：`89c71079fab42a16d00d6428d6a9e21989e35ae8`，候选分支 `codex/round17-memory-deadlines`。2026-11-08 实现及运行验收前登记；最终源码、JAR与结果另行冻结。Round15真实供应商失败、Round16本机原始失败均保留。

## 验收口径

1. 持续小块响应不能绕过模型分配的整次调用预算；取消必须中断已建立HTTP读取，等待连接/任务清理后再确认停止。分别记录读取空闲超时、整次调用截止、取消；用量不明不能写零，不自动重试。不承诺操作系统阻塞DNS或调度/清理的严格实时上限。
2. 显式记忆由用户保存，限工作区共享作用域；绑定当前资料ID、版本、文本SHA256、快照及原文摘录。备注是未验证提示，不是事实。没有模型自动写入或后台向量检索。
3. 记忆有独立修订号，键冲突和并发版本冲突明确拒绝；可更新、过期、删除。资料变化后对应记忆不能用于新任务。删除当前记忆不改写已接受任务的历史快照。
4. 每次Agent提交显式选择最多8条，并批准对应记忆修订；原文及记忆选择都纳入发送许可。任务在数据库事务内冻结记忆，在worker执行前再次验证。跨工作区、来源不符或已过期不得调用模型。
5. 记忆按不可信用户上下文计入预算，不直接进入可引用证据目录；回答仍须检索当前快照、走已有逐条证据核验。记录ID、版本与来源，刷新后可读历史。

## 验证安排

- 先focused回归，再Python、真实MySQL/Redis/MQ Java测试与UI全套；独立新数据库和候选端口8086/8770，不升级8081/8765主服务。
- 本机可控HTTP复现慢响应与取消，保留失败和修复后的原始记录。对比同一语义场景，不将本机耗时当作供应商性能。
- 真实鉴权HTTP矩阵与浏览器验证新建/选择/冲突/过期/删除/刷新。必要的模型响应由明确标注的本机固定响应服务提供，只证明工程链路；不能当成独立人工出题或真实LLM语义评测。
- **本轮外部模型、embedding调用预算为0**；运行环境不载入供应商密钥。不租GPU，不合并PR，不变更主服务。
- 对外保存脱敏响应、指标、源码/证据清单及截图；不发布口令、会话Cookie、CSRF或服务密钥。完成和限制均写入难题记录与桌面简历材料。
