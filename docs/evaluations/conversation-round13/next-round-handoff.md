# 收尾 3 / Round 14 的输入

本轮没有扩数据库连接池或 HTTP 线程。后续以本轮资源观测为基础，先处理真实代码中历史列表取完整行、任务快照重复存储和状态全表统计的成本；不能因为工作区资料少就声称历史数据规模也已经验证。

1. 冻结同一数据生成器、种子和查询集合，分级建立 1 千、1 万、10 万条任务历史。先测磁盘、行宽和索引体积，再决定是否继续扩大，不能把计划规模写成完成规模。
2. 保留旧实现的查询与执行计划，分别测最近列表、翻页、状态统计和单任务详情。记录响应体字节、数据库扫描/排序、提交并发下延迟与连接等待；总数、缺失和失败均保留。
3. 依据证据选择窄投影、游标/复合索引或统计方案。优化前后用相同资料、负载和资源上限；缓存冷/热分开。分页必须覆盖同时间戳、插入与删除、跨工作区隔离，不能只测第一页。
4. 模型路径保留 Round 13 原稿，先离线修订诊断协议：transport 可达条件使用完整 HTTP 成功和已知用量，精确指令遵循单独评分；不能用改协议重算旧失败。新的一次运行仍冻结次数、时间、费用与停止条件。
5. 若下一轮执行 RAG 新样本，冻结开发前与开发后的可见范围；语义按支持/矛盾/不足逐条核对。Round 13 只有离线检索和 tiny，不能以此填补完整 Agent、历史回读或独立人工评测。

本文件是交接计划，以上实验与优化均未执行。GPU 私有部署仍在收尾 8/12，当前不租赁资源。

本轮正式负载另暴露发送端调度迟到：至少一个槽位超过冻结的 100 ms 上限而未发送。后续先分析生成器与采样器共享事件循环、主机调度及观测成本；不能仅凭一次迟到确定根因。若做新实验，使用新的身份、空库及完整分母，事先冻结相同门槛或明确新的测量目标，不覆盖本轮失败，也不靠调高迟到阈值宣称原验收通过。
