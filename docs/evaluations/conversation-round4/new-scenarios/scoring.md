# Frozen scoring protocol

This is an AI-authored synthetic holdout, designed and scored by a separate agent without reading production implementation, old evaluation questions, answers, or reports. It is not independent human evaluation. The only repository source consulted during authoring is `services/workspace/README.md`, for its public API contract. Parent coordination provided execution-usage field names and budget limits only, without implementation or evaluation content.

## Run and dependency rules

There are exactly two isolated workspaces/conversations, three dependent rounds each, seven source documents total, and six rounds in every headline denominator. Sources/questions/gold/rules/runner are frozen before any model call. `manifest.sha256` hashes each frozen authoring artifact; its own SHA-256 identifies the freeze. A successful run requires an explicit GO plus a loopback JVM QA URL and source-freeze identifier. Preserve all raw HTTP bodies, monotonic elapsed time, original questions, request bodies, task IDs, statuses, provider usage, and terminal conversation previews. Freeze raw files with a second SHA-256 manifest before inspecting outputs for semantic scoring. Do not change questions, gold, or rubric after exposure.

Exactly one submission is permitted for each eligible round, with no POST retries, provider retries, model repair, selective reruns, or question repair. Maximum six submitted model tasks; the frozen service limit must be seven model calls/task (six decisions plus one same-model review), hence at most 42 model calls. Service Agent execution budget is 75 seconds/task. Client terminal observation lasts up to 200 seconds/task to accommodate queue/HTTP/persistence overhead. Do not cancel at 75 seconds. A nonterminal task after 200 seconds is an observation/delivery failure; a separate best-effort cancellation is cleanup only and does not become a normal result. Known `execution_usage.model_calls` and unknown usage are reported without replacing unknown by zero.

A round is eligible only if all preceding rounds in its conversation have a usable terminal response. A usable response is a SUCCEEDED task with a nonempty persisted conversation answer; a persisted clarification counts as a response. Clarification without a nonempty answer may instead be established by a nonempty persisted clarification-question field. Semantic correctness is not a run-time dependency gate: wrong but delivered answers continue. Failure, timeout, empty/missing response, or uncertain submission blocks all downstream rounds in that scenario. Those blocked rounds remain in the denominator of six and have no model submission. No outcome from another scenario is imported. A failed root round can therefore yield one observed delivery failure and two blocked rounds; it must not be converted into three observed semantic errors.

## Separate outcome dimensions

Score each round with cited raw-artifact locations for:

1. Delivery: usable persisted terminal response. Values `pass`, `delivery_failure`, `blocked`.
2. Retrieval of required evidence: observed retrieved/source passage material contains every fact in `gold.json.required_evidence`. A source name alone is insufficient; an exact supporting citation/quote is also observable evidence. Distractors do not fail retrieval by themselves. For Q3 pure clarification, record `pass_no_retrieval_required`; if factual interval values are added, the stated evidence obligation applies. If trace completeness is insufficient, use `unobservable`, not an invented pass.
3. Final semantic conclusion: all requested comparisons and combined decisions (or the required missing-data/clarification response) match gold, with no material conflicting conclusion. An unsupported extra material assertion fails this dimension. Correct overall yes/no with wrong numeric comparisons fails. No response is `unobserved`, not semantic fail.
4. Citation entailment: each material source-based final claim must be tied to citations that actually entail that claim under the correct version, profile, entity and units. Exact source existence alone is not entailment. The citation must support the associated measured value and applicable threshold, not merely mention the entity. An accurate inference can use citations to its premises. Explicitly source-backed absence is supported by the memory audit. A pure Q3 clarification without factual claims is `pass_no_factual_claim`; conditional interval values require applicable citations. A citation omitted from an otherwise correct factual answer fails this dimension. When the saved answer/report visibly has no cited association but a detached catalog exists, do not assume attribution.
5. Incorrect refusal: answerable J1/J2/Q1/Q2 must receive the requested determination; unnecessary refusal, insufficient-evidence response or a clarification replacing an answer fails. J3 should acknowledge the genuinely missing measurement, and Q3 should clarify the ambiguous referent; these are correct boundaries and pass. No answer remains `unobserved`.
6. Reference resolution/correction: the entities/pronouns and replacements in gold must be followed. Q3 must preserve the two live possibilities and ask which one; pure clarification passes without inventing a referent. No answer is `unobserved`.
7. Version/profile/scope adherence: preserve the gold's version, profile, region, measurement, and units; do not carry obsolete thresholds or transfer one profile to another. No answer is `unobserved`.

Semantic values are `pass`, `fail`, `unobserved`, or `unobservable`, with the two explicit vacuous-pass labels above. Distinguish an observed incorrect refusal from a task that failed before answering. Report a brief evidence-backed explanation for every fail and every limitation. If uncertainty prevents a defensible judgment, record `unobservable` and do not count it as a pass or an observed error.

## Aggregation and publication

Headline strict end-to-end success is the count of rounds with delivery pass and all six analytic dimensions satisfied, divided by 6. Also report each dimension's satisfied count over 6, observed failures separately from missing/blocked/unobservable outcomes, delivery count over 6, submitted tasks out of 6, and known/unknown model usage against the 42-call bound. Observable-only semantic scores may be supplementary, clearly labeled; never silently drop failed or blocked rounds. This tiny synthetic set is descriptive, not a population-accuracy estimate or independent external validation.

After one run, freeze all raw artifacts first, then score offline using the frozen gold and this protocol. Publish the immutable authoring files, raw files/manifests, source freeze metadata, score records, and a concise report only to `docs/evaluations/conversation-round4/new-scenarios`. Do not publish earlier. Do not modify production code, invoke providers directly, read `.env`, or create git commits.
