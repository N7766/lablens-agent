必须保留的边界：C-21 只确定这一次受控试验的验收结果。月运行费所需的电价、维护和租赁资料未收集，`03-cost-scope-note.md` 明确不可从资料包计算 Dune / Reed 月运行费比较；缺失费用资料不能导致整份验收比较被拒答。不能把节电率变成总成本优势、推广部署批准或其他场地保证。`04-superseded-pilot.md` 的 C-08 读数和偏好属于不同试验，不能替代 C-21。

因果边界：将已知测量代入明确规则可以支持 `rule_evaluation`，不需要证明某项改造如何导致节能的物理机制。反之，验收通过或失败也不能证明设备设计、环境、参数等因素导致了该读数。使用 `rule_evaluation` 标签本身不是语义正确的证据。

必须保留的边界：当前结论仅限 Night Restore R-17。`04-r09-archived-results.md` 是另一版本、另一工作负载的历史 R-09，不能用其双双通过的结论替换本次验收。停电后最大恢复时间未测量，不能由普通 nightly median 推算，也不能将 149 s 或 150 s 当作停电恢复上界。普通 nightly 数据足够判断的部分必须回答，不能因停电数据缺失而拒答整份比较。

因果边界：读数与明确 AND / 不等式规则允许确定验收状态；不允许进一步声称固件、机器规格、失败类型或停电引起了某个成功率/时延，也不能推导线上可靠性、生产容量或稳定性指标。

## 封存后记录方式

1. 先记录每次调用的传输、协议解析和服务端最终验证状态；失败保留在计划调用清单中。失败调用的最终语义结论标为 `not_evaluable`，不能因没有交付错误答案而计作语义正确。
2. 对成功结果同时检查最终 assessments 与最终可见报告。每个关键结论记录 `pass` / `fail`、报告位置和实际引用位置，逐项验证引用是否蕴含测量、规则、算术前提、对象及范围。引用原文存在、schema 合法、派生量审计通过均不能替代这一步。
3. 如果完整请求包含所需资料但最终某行漏引规则或对象，记录该行的 citation entailment 缺口；请求级资料齐全不能自动补全该行引用。保留的旧行与修改行适用同一标准。
4. 分开记录算术/边界/总体验收正确性、完整性、引用蕴含、错误拒答和越界推断。含义充分的等价表述允许通过；未回答部分不能靠草稿、工具轨迹或后续人工解释补足。
5. 本轮最多四次直接 review 诊断属于小样本协议排查。只能报告实际交付和具体内容；不能用它证明完整 Agent 链路修复、检索提升、通用答案质量、线上承载力或私有部署效果。
