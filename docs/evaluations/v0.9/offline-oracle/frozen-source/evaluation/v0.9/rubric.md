# v0.9 选择范围协议对照

本目录的 8 道新题、2 份合成快照及字面预期在真实模型调用前固定。Atlas 使用
空格词数，Lyra 使用人工设计的 token 数；没有进行训练、真实推理或分词测量。
ID 和数值不同于 v0.8。完整 Pareto、筛选后的完整 Pareto、Pareto 内前 2 条并列、
Pareto 内最高值、空 Pareto、token 长度筛选、普通 top-k 和普通极值分别检查。

`dev-cases.json` 的两个 A/B Pareto 任务直接来自 v0.8，是已知开发回归，不能计入
新题分数。默认命令执行字面契约生成的离线参考计划，零 API 调用，参考计划通过
不能算模型成功。`--live` 显式启用真实调用。每题、每协议使用独立上下文，最多
两次请求；不替换失败，不为提供方错误增加重试。两协议每题各两次共 32 个新题
draw，最多 64 次真实请求。开发回归单独目录、单独统计。

v1 使用旧 `metric/ranking` schema，v2 显式拆分排序与选择范围。比较的是整套
协议（提示、schema、编译及版本对应的修正指引），不能把小样本差异因果归于某
一个字段。模型、数据、两次调用上限和请求规则开关一致。温度为 0 也不意味着
提供方结果完全确定；并发会影响延迟。

每个 draw 同时检查：

1. 题目、输入快照、预览、执行、收据与所有查询结果属于声明的快照。
2. 三个明确步骤均存在且没有多余步骤或未处理项；比较方向及 describe 也计分。
3. 检查全部显式查询筛选条件、是否仅 Pareto、选择数量、要求的排序与并列。
   对全集不强加用户没有要求的顺序或并列规则；即使空集碰巧相同，筛选条件与
   `top_k=null` 也必须一致。参数是实际编译后的 QueryRuns，而不是模型口头说法。
4. 结果成员及要求的顺序符合固定字面预期，完整行值匹配当前快照；比较的三个
   数值差值符合字面预期，说明保留全部原文 notes、单位、来源和缺失字段。
5. 收据重算单独报告。可重算不能代替自然语言任务正确性或上述契约检查。

初次成功率通过本地重放已经返回的第一条原始模型消息计算：单次预算、同版
协议、同一数据及规则，然后在本地执行可预览计划并运行相同评分器。重放不
请求模型、不增加实际费用、不产生新的样本。原始第一次回复保留在事件轨迹中。
最终成功率使用真实最多两次调用后的计划。修正请求数、修正成功、规则冲突、
未知费用和所有失败都单列；未知费用不能当作 0。

冻结材料包含运行代码、数据、新旧所需 fixture、契约、评分器和其导入的
`evaluate_snapshots.py`，以及两个协议的提示原始字节与 schema JSON 及其哈希。
模型调用实际使用冻结的题目和快照。source_sha256 与 git_head 用于审查调用前
实现；提供方只返回 model slug，后端模型版本不可验证。记录 HTTPModel 返回的
message/usage，不声称保存了完整 HTTP 响应头或提供方 envelope。

`contract_pass` 仅表示这些人工设计的机器可读契约通过，不是独立人工审核、
一般自然语言正确率、真实实验效果或统计显著提升。开发及新题均不得在看完
模型结果后修改预期以提高分数；修复实现后如重新评测，应另建目录并披露原因。
