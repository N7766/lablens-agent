# Round 7：把证据不足与问题不清区分开

本子项实现 `lablens/clarification_policy.py` 与 `tests/test_clarification_policy.py`。这里只记录确定性动作策略、原失败回放和取舍；真实模型是否能给出完整结论，要看本轮独立封存的输出与语义评分。没有修改第六轮封存资料，没有运行外部模型，也没有把开发回放计入新准确率。

## 原始故障与能够确认的事实

[第六轮 kl-t2 原始任务](../conversation-round6/runs/round6-once/kl-t2-final-task.json) 中：

- `request.question` 明确要求：更新对那次运行的判断，逐项回答是否至少重试一次、失败原因能否归于上游限流，并给出最小所缺证据、注明补充信息来自用户。
- 第一次 `search_workspace` 已取得 `kl-run`、`kl-retention`、`kl-alert`。这些资料包含最终 `SUCCEEDED`、缺少尝试计数与历史失败记录、建立重试和归因所需的证据类型。不是一次零命中检索。
- 第二次模型决策选择 `request_clarification`；原文询问用户是否还有尝试记录、是否需要搜索日志。`result.assessments=[]`，未进入最终证据复核，`result.status=clarification_required`。
- 第二次响应后还剩约 67 秒。不能把这次遗漏解释为 75 秒预算已经用尽，也不能据此认定所有其他超时的成因。
- 原 `answer_contract.requires_clarification=false` 只表示没有命中既有窄指代规则，**不证明通用语义上已经消除了所有歧义**。

[原 gold](../conversation-round5/new-scenarios/frozen/gold.json) `turns.kl-t2` 允许在实质不足结论后邀请补充资料，但要求先说明重试未知、失败未成立且已知最终成功、限流不能归因，以及两类最小证据。只追问更多资料不能完成这些要求。原评分和问题保持不变。

## 最小设计

`clarification_policy(question, *, lookup_count, requires_clarification=False)` 只读取当前用户问题、已完成检索次数和既有强制澄清义务。它不读取来源内容、旧助手回答或固定状态；不从“没有资料”推断“历史没有发生”。

只有同时满足以下条件，才从**下一次既有模型决策**的可选动作中移除 `request_clarification`：

1. 当前用户明确要求“结论/判断”以及“所缺证据/信息/资料”；使用有限的通用中英文词法，不含运行编号、日志、重试、限流或本题名字。
2. 至少完成一次检索，包括合法的 `no_hits`。失败的搜索不能增加计数。
3. 没有命中既有强制指代澄清规则，没有明确要求先澄清，也没有否定给结论的请求。

模型仍可选择已允许的检索或提交报告。模型选择报告后仍走完整来源校验和固定复核。策略不构造答案、证据或 verdict，也不承诺完整回答一定发生。`no_hits` 后只能让模型报告有界不足，不能据此断言事件未发生。

首次决策始终保留澄清，所以缺目标、缺含义时可以先问；既有双对象加单数指代义务在任何阶段都优先。普通问题没有明确“结论 + 所缺证据”请求时，检索后也保留澄清。

## 接入约束

- 每次形成 `decision_tools` 后按 `allow_clarification` 过滤工具；把策略版本、规则、lookup_count 与两个 `verified=false` 边界放入当前模型请求的可审计元数据。
- 同时校验返回的动作属于当次允许动作。不能只改 schema、仍接受模型越权调用被移除的澄清。
- 越权动作按协议错误停止，不追加修复模型调用，不把原澄清伪装成用户已经澄清，也不未经复核构造报告。
- 可追加 `POLICY_INSTRUCTIONS` 解释“缺证据不等于问题不清”，帮助模型理解受限动作。该文本没有测试题专用答案。
- 避免仅为这项策略新增跨语言 trace event。第六轮曾发生 Python 新事件未进入 Java allowlist，导致异常轨迹整段缺失；已有请求上下文即可保留本项策略证据。若 root 选择新增事件，必须同步契约与错误路径验收。

## 过程中的难题与取舍

| 难题 | 采用的处理 | 保留的限制 |
| --- | --- | --- |
| 把“没有证据”误当“需要先问用户”，导致可答的不确定结论被丢弃 | 对用户明确要求给结论和缺证据的请求，在成功检索后约束下一步可选动作 | 无法保证模型选择报告而非继续搜索；完整性仍需评测 |
| 一刀切禁用检索后的澄清会损害真实歧义场景 | 首次澄清、既有指代义务、明确先澄清请求和普通问题保留 | 新出现且窄规则没捕获的语义歧义仍可能漏掉；不声称通用判歧 |
| 直接把澄清文字改成不足报告会混入未经核验的事实 | 不转换动作；让同一次正常决策产生正式报告，再使用现有复核 | 它是动作约束，不是完成度修复器 |
| 临时再问模型一次会增加预算和改变失败分母 | 在请求发出前限制 schema，越权即明确停止 | 真正的协议失败不会被隐藏为成功报告 |
| 用来源里“没有日志”等词触发规则容易被来源影响，且对题目过拟合 | 仅处理用户当前的通用报告要求，不读来源、运行号或业务关键词 | 词法表达覆盖有限，部分等价问法不会命中 |
| 中英文否定、先问后答可能与正向词同时出现 | 先澄清和否定请求优先，并保留回归控制 | 不处理所有自然语言否定、转折和元语言引用 |

没有采用“发现错误澄清后加一个中性问题槽并直接进入 review”的备选方案：这会把模型本来没有提交的命题交给固定复核，容易让机制看起来完成了用户要求，而实际只生成一个泛化的不足行。若未来采用通用任务分解，需要独立设计当前问题到槽位的覆盖协议，不能把本题答案写进槽位。

## 开发验证

命令：`.venv/bin/pytest tests/test_clarification_policy.py -q`。

初版 **40 项通过**；自审增加“先问清楚”、英文 Before-giving 和中英文显式否定请求后，**44 项通过**：包含原始 `kl-t2` 封存结果回放、通用中英文请求、零命中语义边界、首次缺目标、真实双对象指代歧义、先澄清请求、否定结论请求、普通问题和无效状态类型。原失败仍保持 `clarification_required`；回放只确认在新策略下，原第二次决策不会再提供该动作。

自审发现通用前置词“先问清楚”与英文“Before giving ..., ask ...”没有被初版先澄清规则覆盖，补入 4 个控制并扩展同一优先规则。没有引入业务词或测试题专用条件。Root 随后补入 3 个“资料冲突时澄清适用版本/对象”的条件性请求，合并后的本模块为 **47 项**；用户明确要求先澄清的优先级继续保留。

这些测试既不发外部模型请求，也不证明最终答案正确。Root 接入后的模型/工具调用数量、对越权动作的拒绝、报告复核链和真实模型评测，应分别记录在本轮总报告。

### 接入前内部复核发现

另一开发 AI 提供了条件澄清反例：“Give conclusions and missing evidence, but ask me which deployment if the records identify more than one.” 以及“若记录对应多个部署就向我确认对象”。初稿只识别 first/before/先，错误禁用了明确保留的条件澄清。现把用户明确要求确认对象/范围/版本的措辞列为优先分支，新增三条回归。该修复仍是有限措辞识别，不能声称通用语义判歧；保守保留澄清可能放过部分错误追问，但不会强迫模型猜对象。
