# Round 7 优化与排查过程

本记录区分执行前实现、唯一真实采集、封存后修复。没有通过重跑覆盖首次失败；原始10题和gold保持，后置代码不能套用旧分数。

## 执行前的发现与取舍

- 比较覆盖原型曾借用相邻指标的变更谓词、把问句当答案、从多指标标题借用解释。先保存失败反例，再限制当前问题、对象与子句；不补猜测值。见[开发记录](coverage-development.md)。
- 澄清策略需保留“若有多个部署先向我确认”的明确偏好；只识别“先问”不够。加有限条件请求识别与拒收路径测试，未声称通用歧义判断。[记录](clarification-development.md)。
- 复核短ID必须在调用前验证完整有序的原命题映射，返回后拒绝伪造statement、重复/陌生/非字符串ID。响应构造样例少452字节，但请求多184字节；没有预设收益或把构造样例当实测模型响应。[记录](review-development.md)。
- 独立工具复审查出五类假通过风险：未完成评分、strict与诊断矛盾、错误纯澄清通过、候选/输入身份失效、token分项与汇总不一致。修复后75工具测试通过，原反例重放，再冻结。[复审](pre-run-review.md)、[工具过程](harness-development.md)。

**确认：** Cedar原稿已有两个整体判定，coverage漏认中间试验ID，review前误拒；Harbor“也不通过”漏认造成多槽；Sable/Quill错配、alert引用配置和错误比较拒答直接见原报告。**排除：** 本次Cedar不是模型超时、缺来源或调用预算耗尽；Alder比较漏答不是未检索到两个范围。**未知：** 移除冗余槽后的模型答案/时延；提示词中“历史助手文本不是证据”是否导致比较拒答；短ID是否改善实际输出成本。没有消融，不能给出因果断言。

## 封存后的处理

只修确定性的覆盖缺陷并做原稿离线回放；独立复审又发现P99指标被误认试验ID及跨对象问句污染，纳入同一离线修复记录。语义主语与引用错配、最小证据漏答保持未解决。过程见[后置修复](../../post-evaluation-round7.md)，原始评阅和失败回放继续绑定619c051。

浏览器只读打开报告、合理澄清、失败终态和轨迹；刷新后再次选中同一记录并比较正文。定位器曾同时命中隐藏会话文本与可见报告，改为页面已有的`#answer`后继续，属于自动化定位问题，未修改应用或提交新任务。

浏览器验证完成后按PID、启动时间、命令、cwd和监听端口核实专用QA服务，确认无活动任务再SIGTERM；5张表的计数、内容哈希及任务状态保持，主服务HTTP200与保护进程身份保持。数据库和封存材料保留，无强杀。[关闭证据](qa-cleanup.json)。

质量门未过，因此不合并、不升级主服务。失败原稿、单次调用、严格评分、内部异议及仅离线修复一起交付，避免把工程检查数写成答案准确率。

浏览器还暴露既有拒绝事件文案过度承诺“已向模型返回原因”；Cedar路径实际直接停止。封存后仅改为“原因已记录”，保留旧截图，另跑前端逻辑回归；没有为这处文案重新部署或发送模型请求。
