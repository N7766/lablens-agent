# Round18 / 收尾第7轮预先协议

基线 `2170b132f4756a2aa624ce6cc03799c4807d5bf5`，上一轮PR #62仍为draft，本轮分支 `codex/round18-checkpoint-recovery`。目标是有界用户历史摘要、MySQL工具边界检查点、显式恢复和未知结果阻断。

## 固定边界

- 外部模型、embedding、GPU费用预算均为0。使用本机固定响应验证真实HTTP、MySQL事务、鉴权和恢复链路；不作为真实LLM语义验收或模型压测。
- 检查点只在完整工具批次边界保存；每个可能产生外部调用的操作先持久化“已准备发出”。不能原子提交数据库与供应商请求，故该标记只说明可能发出，结果缺失保守视为未知。
- 显式恢复使用原冻结资料、问题、会话和记忆，继承已消耗调用和活动时间预算；等待人工恢复的离线时间不计入活动执行预算。最多创建一个恢复子任务，不改写原任务结果，也不自动重放已完成工具。
- 结果未知、检查点不完整、版本不兼容、失效来源或记忆、预算耗尽均明确结束。恢复不是供应商取消、费用结算或任意故障下的exactly-once承诺。
- 摘要保留用户原话及序号/快照来源，不把旧回答总结为事实；容量不足明确要求新会话，不静默丢弃旧否定和约束。

## 验证

1. Python恢复状态、完整工具批次、预算、来源/配置不匹配、未知请求及摘要回归。
2. Java真实MySQL检查点单调版本、owner/lease fencing、唯一恢复子任务、事务Outbox、并发提交、鉴权与会话冲突。
3. 真实双服务固定响应链路：在已落库工具边界注入中断，重启worker，显式恢复；验证检索不重复、结果来源不变、刷新可回读。另一任务在在途请求中断，恢复被拒绝且调用数不增长。
4. 浏览器核对明确发送许可、未知结果提示及历史关联；新建工程夹具允许写入，旧模型评测保持只读。
5. 运行相关完整工程套件和精确提交的CI；冻结运行源/JAR，保留初次失败与最终结果、原始调用和清理记录。

候选资源：8086 JVM、8770 worker、8771固定响应、6383 Redis、5674 RabbitMQ与独立数据库；8081/8765主服务保持现状。本轮工程验收不会替代旧语义失败，PR保持draft。

## 执行时补充（保留首次结果）

首次脚本在worker被杀后、尚未重启时受理恢复子任务，调度器立即失败；仅有1次本机固定响应。原任务和失败子任务、冻结清单保存在initial-run。只修测试脚本就绪顺序，在新合成工作区执行修正版；生产代码及JAR不变。修正版矩阵6次固定响应（含浏览器预备任务），浏览器显式恢复另2次，本地合计9次，外部预算仍0。代理另计检索HTTP，验证恢复不重放不只依赖报告trace。
