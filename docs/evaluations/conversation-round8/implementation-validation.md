## 实际发现和取舍

- 单侧仅提peer会误拦“与另一个对象不同，它通过”的合法对照。收窄为解释和所选引文同时只提另一对象；其余明确记未验证。没有把名字出现当成谓词蕴含。
- 配置scalar词法曾漏掉句末`2.`，还把`2+1`/`2,000`等截为`2`。反例先失败再修，断言和来源双向控制；表达式不自动计算，不作为字面配置锚点。[绑定过程](binding-development.md)。
- “不得新增对象”与更正前后比较矛盾，改为不得新增未请求命题或行；同一显式比较行允许依据当前来源描述两个用户范围。[复核过程](review-development.md)。
- 新规则增加上下文开销。首轮完整Python为1394通过/1失败：旧测试写死18000估计单位，现已在第一次模型调用前超限，没测到预期的工具返回后超限。测试改为先在1024窗口只测首请求大小（0模型调用），再设置刚好容纳首请求的隔离窗口，验证检索完整保留、第二次调用前停止。生产65536窗口及所有预算未提高。
- 新链路测试初次3失败，是fixture仅设置API地址/假key而缺模型名；因此正确在review发送前停止。补齐受控模型名后三个案例通过，没有真实provider请求。
- 评测器还需验证run-summary自身已封存，否则未封存台账可能参与评分。新增拒收测试，旧round7文件未修改。[工具过程](harness-development.md)。
