# Round 8：跨范围比较与最小证据复核

本记录只说明实现、原始失败定位和离线测试，不把提示变化或受控返回当成真实模型通过。Round 7 原始输出、gold、标注和分数未修改。

## 已确认的问题

- [ar-t2 原结果](../conversation-round7/runs/round7-once/ar-t2-final-task.json)：当前检索同时含两个集群的签字配置及两版策略，模型仍以“前轮是另一个对象、没有前轮对当前对象的回答”为由拒绝三个比较。用户明确要求更正对象前后的结论比较；不需要前轮先讨论新对象。旧助手文字不是事实证据，但可以由当前来源分别核对两个用户范围再比较。
- [kl-t2 原结果](../conversation-round7/runs/round7-once/kl-t2-final-task.json)：历史重试和限流归因均保持不足，却未完整说明各自最小观测和关联条件。现有 inventory 明确列出了判断需要的记录。答案还重复了本轮未问的配置并误引告警卡；初稿约束和引用绑定由本轮其他改动处理，不能仅靠本复核提示宣称已消除。

## 最小实现

[`comparison_context.py`](../../../lablens/comparison_context.py) 只根据**当前用户明确要求**生成复核任务说明：

1. 沿用现有有限语法抽取“上一轮哪些变更、哪些保留”的 2–6 个比较项，不从资料或旧答案推测比较数值。
2. 以前文 `recent_user_messages[-1].question` 的引用、seq 和 snapshot ID 定位最近一条原始用户问题；正文不复制第二遍，不读取助手答案或置顶 focus 来填充旧范围。最近记录缺失或格式无效时标为 `unavailable`，不悄悄退回更早问题。
3. 列出本轮可见 passage IDs；`scope_resolution_verified`、`evidence_coverage_verified`、`semantic_correctness_verified` 均为 false。模型仍须解析两个范围并分别查证。不同对象或版本本身不构成拒答理由；无法明确旧范围、缺某一侧来源或来源矛盾时必须准确保留那一侧的不确定性。
4. 当前用户明确要“最小证据”时，要求每条未知结论说明决定性观测及对象/运行/attempt/时间版本关联。优先引用资料中的 inventory；来源未规定的核验方式要标为建议。区分事件是否发生与原因是否成立；不能把最终成功推成此前有失败。用户线索仍须归属用户。

[`rag.py`](../../../lablens/rag.py) 只在固定行的 scoped review 注入说明，保留 1 次复核、2600 输出 token、最多 8 行和 a1…a8 协议。报告中 `generation_review.review_context` 保存版本、实现哈希、资料 ID、比较项、旧用户范围可用状态和上述 false 边界；不保存新的“已核实历史记忆”。固定行复核只能补全现有相关行的解释，不能新增漏掉的命题。

跨对象比较可以在原行解释中说明两个用户范围；“不得增加对象”被澄清为不得增加未请求命题或行，避免与比较义务冲突。这不把旧用户问题里的值提升为已核实事实。若旧助手说错，应区分修正答案与业务系统真的发生变化。

## 验证和开销

`tests/test_round8_review_context.py` **34 项**通过；加上既有短 ID 协议和 answer-quality 回归，共 **127 项**通过（1 条既有 Starlette/httpx 弃用警告）。包括：

- 读取封存 ar-t2/kl-t2 的真实原稿和检索资料，核对请求结构与来源 ID；服务端补槽仍是待复核，不直接改成支持。
- 无前文、助手中才有前文、过期 pin、无效最近记录、多个对象、代词、恶意历史文字均不获得“范围已核实”标记。
- 用户未要求比较/最小证据或明确否定时，不从历史问题推断新义务。
- 受控 provider 分别返回支持比较和旧侧缺资料，均仅 1 次调用；值和 verdict 来自测试返回，不宣称模型会正确生成。
- 旧非 scoped RAG 保持原协议；原始输入不变，复核 ID 和陈述映射不变。

控制构造使用 Round 7 原稿/来源、取样时同一份共享 instructions 和 contract，仅交换 `55f7c3f` 与当前 `_generation_payload` builder。ar-t2 请求序列化字节 **21,955 → 24,233（+2,278）**，kl-t2 **19,248 → 20,808（+1,560）**。这是本处显式任务说明的局部开销；没有包含本轮其他共享模块变化，**不是最终候选的完整请求大小、全链路优化幅度、实测 token 或延迟**。未增加模型调用、输出预算或超时上限。

第一次联合测试发现 `test_runtime_telemetry` 仍断言 v8，而本轮入口已升为 v9；该版本期望由入口维护者同步，未把版本断言失败包装为模型故障。

同步 v9 期望后，将 runtime telemetry 纳入上述组合，**140 项通过**；没有改变旧模型结果或发起外部请求。

## 尚未证明

任务说明不是语义校验器。有限中文/英文列表语法并未覆盖所有表达；最近用户问题可能仍含模糊指代，当前资料也可能不够。旧的不足结论 named-ID 检查未在本轮扩大成完整历史 NER；含特定标识符的合法旧范围解释仍是已知边界。真实模型是否完成跨范围比较、最小证据是否足够、是否减少错误拒答，应由本轮冻结后的一次评测独立核对，不能从这些协议测试推导。
