## 一次运行边界

- 单张 RTX A6000 48GB、100GB容器磁盘；Qwen2.5-7B-Instruct 固定 revision，vLLM 0.32.0 固定镜像 digest、精确 CPU TorchCodec wheel 和 AVX guard；沿用仓库 profile。
- 首先只运行3次兼容探针：中文精确输出、结构化工具选择、v4逐ID复核。任何一项失败则不进入 Agent 阶段。
- 全部兼容通过后，仅运行原先已暴露的1道合成 Agent 回归题，最多2次动作决策和1次复核。总上限6次模型请求；未知、超时、范围错误及机械验收失败均不重试，不利用剩余额度改题。
- 仍由不可退款的发送预约、逐阶段单次领取和不同上游/本地key约束；worker不持上游key。超时40秒/请求，Agent整体80秒。调用额度不是云端账单硬上限。
- 从创建租赁意图开始计时，最多2小时/10美元，包含准备、下载、运行、存储和传输。1小时50分前导出并清理，超时清理只绑定本次明确确认的新实例。不能操作其他对话或旧实例。
- 当前只读候选报价见 [offer-review.json](offer-review.json)，2小时加51GB保守传输估算约1.20美元。报价不是账单或承诺；创建前复核可用性、价格、完整镜像及停止条件。

## 已知回归的预先评分

题目、2份资料和预期与原Round19c相同，不称新题。配置记录 `cache_enabled: true` 只能支持配置事实；没有历史运行日志时，不应声称历史实际使用缓存，也不能拒绝已经有材料的 SFT 基线。

分别报告以下维度，不以HTTP200或引用文本存在代替其他维度：

1. **检索**：真实工具选择、BM25索引复用、两份需要资料是否实际可见；来源版本、文档/片段/精确偏移及哈希一致。
2. **工程链路**：最多3次Agent请求，已发生用量/未知用量保留，终态与MySQL/新认证会话/刷新回读一致；失败时无正常answer/claims。
3. **结论与覆盖**：SFT基线有资料支持；配置和历史的statement/basis/verdict/explanation分别一致；整题不能只回答配置而遗漏历史问题。
4. **拒答**：历史执行未知属于合理不足；把已引用的配置事实或SFT基线也拒绝属于错误拒答。
5. **机械与语义分别记录**：acceptance-v2只用有限完整表达且独立于生产guard；未知同义表达可能机械失败，应另交独立AI审阅，保留二者结论。不得为本次输出扩大模板或重算原始检查。

原始S5失败不覆盖。新结果使用独占目录，先冻结资料/模型/代码/请求/评分，再发送。成功Agent的完整HTTP原文若仍无法导出，应明确保留的是规范化动作/review/工具轨迹；不要宣称补齐未记录的数据。新调用后仅做只读审阅，不补推理。
