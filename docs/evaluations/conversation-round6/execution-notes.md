# Round 6 优化过程与难题记录

本轮不只记录通过项，也记录新防护带来的回归和不能下结论的地方。候选 `dd225edf` 只做了一次授权模型采集；后续都是对封存证据的读取、标注和离线复现。

## 1. 先补评测工具的可靠性

准备阶段复用旧 6 轮和原新 4 轮，保留不同 gold。审查发现三个工具缺口：输入只在启动时校验、aggregate 用量可能覆盖未闭合 request 的未知状态、评分指针只检查列表非空。修复后 v1 原字节与改动前工具另存，生成 v2 再由 root 批准；此时外部模型调用仍为 0。

验证结果：37 项离线测试和另一 AI 的 10 项修复复核通过。v2 每轮及 finally 都验证原批准输入 SHA 与文件，summary 保留批准 identity；负 token / 未闭合 / provider 接受未知不得变成全知；评分引用必须能定位到 raw/input 封存文件及 JSON 或行范围。详见 [推理前修订](pre-run-revision.md)。这些检查保证过程可追溯，不保证答案正确。

## 2. 多轮依赖会放大首轮交付失败

Cedar 与 Harbor 的首轮各失败一次，四个后继轮按协议阻断。因此“只发生两个失败任务”并不等同于“十轮完成八轮”；实际是 6 次提交、4 个持久化响应、4 个依赖未提交。执行器没有拿旧答案填充历史，也没有把依赖问题独立再问一次。

这一轮保留了全部计划分母。旧六轮没有可评分的最终回答；不能拿已经检索到的正确资料或中间草稿抵消最终未交付。

## 3. 新完整性防护出现了确定性误拒绝

Harbor 的模型原稿有 8 条，已经包含两个候选的“无法通过验收”。新 coverage 规则漏认这个总判定表达，准备再补两个总判定槽；超过 8 条上限后工具拒绝，模型被迫进入额外 decision。第三次 decision 只剩约 8.18 秒的 decision 可用时间，于约 55.65 秒失败，完整 review 预留仍有约 19.36 秒。

已确认：原稿经引用选择和逐条验证可接受；对实际原始参数进行离线复现，确实在补槽时产生 `>8` 错误。这是新增防护自己的回归，不应笼统解释成“模型平台慢”。排除项：并非发生第三次 review，也不是在 75 秒总预算用完后才失败。

处理：root 选择保留该候选失败、不升级主服务、不补跑模型；将最小识别修复单列为运行后的离线修复。尚不能确认：如果没有这次误拒绝，剩余模型请求一定成功。一次反事实推测不能替代真实验收。

## 4. Cedar 超时原因与 Harbor 不同

Cedar 原稿为 8 条，coverage 没有添加槽；第 3 个模型请求直接进入 review。当时只剩约 24.22 秒，review 约 25.21 秒后返回超时，worker 总计 76.032 秒。这里有总预算耗尽标记。

证据支持“review 超时且剩余预算有限”，不支持“补槽导致 Cedar 超时”。也不能只凭本次观测把原因完全归于网络、provider 排队或某种提示词长度；本轮没有对这些因素做独立控制实验。

## 5. 检索正确仍可能漏答或错误澄清

原四轮都检索到了 gold 要求的必要来源，但只有 `ar-t1` strict 通过。`ar-t2` 输出新数值而漏掉用户明确要求的变更/保留比较；`kl-t1` 核心正确，但原 gold 的细节要求仍不齐；`kl-t2` 明知 evidence inventory 给出了缺口及最低证据要求，仍只问有没有更多日志，未回答限流原因和最小证据。

这说明工具调用成功、来源存在、引文内容正确，都不能自动推出答案已经完整。后续需要覆盖“资料足以给有界不足结论时不要只澄清”和“多轮更正后逐项比较”两类实质失败。不能仅增加关键词来制造通过；应保留对无依据历史推断和真正缺信息问题的反例。

## 6. 分数与费用的表达边界

旧六轮 strict 2/6→0/6，原四轮 0/4→1/4，前者是交付退化、后者只有局部改善。不能挑后者宣传整体提升。4 个成功任务中 1 个只是澄清；应写“3 份事实报告 + 1 次澄清”。

17 次模型尝试都有生命周期记录，2 次 timeout 的 token/provider 接受未知。58,199 是 15 个已知响应的 token 下限，不是完整用量和费用。保持 decision/review 分开，避免把次数已知误写成费用全知。

## 下一次验收应完成什么

1. 对 post-evaluation Harbor 修复做新的源码身份记录，先通过包含真实原稿的离线回归和不误识别反例，再另行授权有界真实回归；本轮成绩保持不动。
2. 处理 `ar-t2` 的明确比较漏答与 `kl-t2` 的错误澄清，分别检查检索、回答实质和来源边界。保持 75 秒与原模型调用上限，记录是否引入新的拒绝或时延代价。
3. 在已暴露失败修复后另建题干和 gold 对齐的新评测版本，明确人类/AI作者身份，避免把旧题回归叫成泛化评测。

这些是下一次验收条件，本轮没有追加推理，也没有把候选包装成已完成上线或模型质量过关。
