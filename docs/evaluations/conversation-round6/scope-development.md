## 设计与可接入接口

### `measurement_scope_findings(raw)`

检查每个 assessment 的解释，不受 verdict 限制；supported 的 statement 也作为肯定断言检查。insufficient/contradicted 的 statement 可能是待判断或被反驳的命题，因此不会仅因命题本身含“未测量”就拦截。

对窄语法命中的历史未测断言，要求其**本条已选引文**中的同一子句明确写出未测量，并匹配命名对象、运行编号与指标签名。没有值、unknown、null、N/A、未提供记录，都不能代替明确未测量。引文包含其他对象或其他指标的 `not measured` 也不能放行。

同对象同指标同时有明确未测与已测的选中来源时，返回冲突 finding。允许有来源的归因表达，例如“报告称未测，另一记录称已测，两者冲突”，而不把来源中的说法直接当成已确认历史。它不会到未选中的文档里补救当前结论，不会修改原始来源，也不自行替换出新的事实。

输出含 `assessment_index`、规则名、被检查断言和匹配计数；root 将其接入草稿审阅契约和最终发布检查。被拦截后的通用说明需要明确“原生成结论未发布”，不得将检查失败改写成“工作区没有资料”。

### `user_reference_contract(question, context=None)`

返回与原 `answer_contract` 兼容的字典。优先检查当前用户问题重新引入的候选对，其次才使用最近一条用户问题。模型回答、固定状态和检索文本都不能创造候选对象。

把最后一段含指代/复数请求的子句作为请求范围：“两者都是候选。请按它写”仍是单数歧义；“请分别给两者结论”不会被强迫澄清。当前或前序同一用户问题中的明确对象缩小、当前问题中的明确更正、最新一次单目标问题，均优先于更旧的候选对。

### `named_user_pairs(text)`

返回 `(start, end, [left, right])`。供总体结论槽复用相同的受限名称识别，避免两个模块各自把普通英文词识别为候选。该原语不判断候选对是否仍是最终请求范围；调用方仍须处理后续更正。

## 开发中遇到的难题与处理

| 难题 | 处理与新增控制 | 保留边界 |
| --- | --- | --- |
| 只看 verdict 会遗漏 insufficient 解释中的确定历史断言 | 所有解释都检查；只有 supported statement 视为肯定主张 | 不是通用事实核验器 |
| 引文某处出现“未测量”，但对象或指标不同 | 同子句绑定对象、run 与指标；加入 Quill/Sable、R-17/R-09、成功率/停电恢复的替换控制 | 需要明确命名和支持的指标词法 |
| 一个长句同时讨论两个对象，任意 `not measured` 容易错误放行 | 拆分对比边界；同子句有额外候选名时不据此认证目标未测 | 合法的复杂复合句可能保守拒绝 |
| `In R-17, Sable ...` 被逗号切开后丢失运行范围 | 保留短运行前缀；同源允许、换成 R-09 拒绝 | 不解决跨段落隐含运行范围 |
| 来源带一个额外 run 标签、句首 The，可能造成误拒 | 常见普通词过滤；未指定 run 的断言可匹配来源里一个额外 run 标签 | 多个冲突 run 或候选仍需明确对齐 |
| “没有证据表明未测量”与“未测量”极性相反 | 将明确不确定/否定蕴含表达排除；后置不确定提醒不能洗掉前置确定断言 | 未覆盖所有中英文句式 |
| Cedar 的“都还是候选”不是最终复数请求 | 区分前面的候选介绍与后面的单数请求 | 不做通用指代消解 |
| 放宽 Dune/Reed 名称后可能把 Latency/Throughput 当对象 | plain English 名称要求比较/候选语境，并过滤普通指标/操作词；保留 gpu-a/gpu-b 等标识符 | 名称识别仍是受限词法启发式 |
| 原 numeric-only 测试包含无引文的 `no measurement was made` | 集成测试最初出现 2 个失败；该后半句确实是新规则要拦的历史断言，root 将 numeric-only fixture 改为“没有提供测量记录”，另保留新的范围回归 | 没有为让旧断言通过而放宽范围规则 |
| 总判定补槽可能无视同轮缩小范围 | 只读审阅发现“比较 Dune/Reed，随后只给 Dune 总判定”会误加 Reed；已向 root 提供可复现文本和共享名称接口 | 由 root 在 coverage 模块处理，不在本模块制造答案 |

## Prompt 建议与发布行为

1. 资料包没有值，只能写“本次提供的资料没有该值/无法据此判断”；不能写成历史运行未测量、未执行或未发生。
2. 明确声称未测量，需要选择同对象、同运行、同指标的明确来源；unknown、空字段和其他指标未测量不是替代证据。
3. 选中来源彼此矛盾时保留双方及范围，避免任意选择。来源归因与事实肯定分开表达。
4. 确定义务要求澄清时只提供澄清工具，不先检索或生成报告；用户已明确纠正为单对象时不强迫澄清。

- 本模块最初 63 项回归通过；补入 run 前缀、同句错对象、gpu 标识符等控制后 69 项通过；最终公开接口及否定证据表述控制加入后 **72 项通过**。
- 实际命令：`.venv/bin/pytest tests/test_evidence_scope.py tests/test_answer_quality.py -q`，接入与旧 fixture 调整后 **136 passed，1 条既有 Starlette/httpx 弃用提醒**。
- 对第五轮旧题 6 份最终结果离线重放范围检查：只报告 Harbor-t2 的 assessment 2 历史未测量越界，其他 5 份该窄检查没有 finding。这不代表其他答案正确；它们原有算术、覆盖率或澄清失败仍保留。
- 真实回归直接读取原始 Harbor-t2 输出和 Cedar-t3 请求，而不把手写近似案例当成原故障。
- 以上均是确定性开发回归，无模型调用、无新增账单、无延迟/吞吐压测。新的语义正确率要由完整冻结评测另行给出，不能从本表推导。

## 已知限制

该检查不是 NER、跨语言语义蕴含或因果判断系统。名称和指标语法之外的表达可能漏检，省略主语、复杂共指及复杂复合句也可能被保守拦截。指标集合相等检查无法证明场景/单位/时间窗的所有细节。归因来源只代表文本中的说法，不认证来源真实性。空 finding 仅表示这些有限检查没有发现问题。

生产范围检查在 root 接入前后的具体 source hash 由本轮总 freeze 统一记录，避免把子任务暂时测试次数当成最终仓库完整测试次数。
