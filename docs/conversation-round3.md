# LabLens 会话第三轮：逐条证据检查与受约束复核

日期：2026-10-29。从 `201fb3d` 继续，仍属于 v0.13 候选迭代，没有发布新的正式 release。

## 背景与本轮目标

第二轮的新题中，6 轮全部执行完成，但严格通过仅 3/6。主要问题是阈值判断只引用测量值、复核新增无依据的分项拒答，以及指代含糊时直接回答两台机器。第三轮先约束回答与复核，再考虑长期记忆。未充分核对的模型结论若自动保存为长期事实，会传播到后续会话。

最终代码为 `5a96b33`，补充测试提交为 `fed3bd6`。最终候选只依据已暴露的旧题做两次开发迭代；新题运行前冻结源码、问题、资料与评分要求，开始后未改生产代码或提示词，也没有隐藏重试。

## 项目设计与改进

现有 JVM/Spring Boot 服务负责工作区、MySQL 资料版本/会话/任务与取消状态；Redis 负责缓存和临时协调。Python Agent 调用本机 HTTP 检索和来源核验接口，通过 DeepInfra 的已配置模型选择动作并生成报告。本轮没有增加数据库或框架依赖。

| 位置 | 本轮实现 | 边界 |
|---|---|---|
| 回答对象 | 当前问题与上一条用户消息中，特定“并列命名对象→单数指代”形式先澄清；明确更正优先 | 有限词法规则，不是通用指代解析；旧模型回答不是事实依据 |
| 复核范围 | 固定初稿命题集合，每项恰好一次；允许纠正判定、解释和引文 | 不保证初稿覆盖全部用户要求；复核仍使用同一模型 |
| 逐条引文 | 肯定判断的陈述和解释中的带单位数值，必须能在该条选定片段或有限明确算式中找到依据 | 不认证对象、指标、方向和语义蕴含；矛盾/不足解释中的假设数值不做此项检查 |
| 拒答对象 | 拦截特定新增命名对象的无依据有效性/权威性拒答，保留合法来源标识说明 | 不是通用实体识别或拒答分类器，普通名称仍可能漏检 |
| 原文片段 | 1000 字符以内保持整行；超长行优先句末/空白边界，保留精确偏移与片段版本 | 极长连续文本仍按上限切割；保持完整片段不等于模型会选对引文 |
| 澄清协议 | 模型省略可选 choices 时，绑定已经从用户消息提取的对象，记录 choices_origin；显式非法选项一次结束 | 不凭空补充对象，不自动提交下一轮 |
| 可追溯性 | answer_contract/evidence_quality、源码 SHA、片段版本、来源快照、检查问题均随报告持久化 | 规则通过不显示为语义认证 |
| 资源控制 | 75 秒总预算，最多 6 次决策与 1 次复核，沿用取消传播与已知/未知用量 | 没有供应商自动重试；未知用量不是零用量 |

规则拦截时写明“生成内容未通过检查”，不把生成错误包装为“资料不存在”。不自动按数值给模型补引文。

## 真实模型评测：分别保留成功与失败

### 已暴露的旧题回归

同一组 2 场景、6 轮、7 份合成英文资料，以中文多轮追问。两版均一次运行，问题与原始 gold 不变。

| 候选 | 执行完成 | 严格通过 | 调用/已知 token | 解释 |
|---|---:|---:|---:|---|
| [首版 bd7e165](evaluations/conversation-round3/development-first/README.md) | 5/6 | 1/6 | 22 / 83,564 | 原片段截断阈值；遗漏要求的差值；正确澄清因缺少可选 choices 被重复拒绝 |
| [最终版 fed3bd6](evaluations/conversation-round3/development-final/README.md) | 6/6 | 6/6 | 17 / 69,974 | 完整片段与澄清绑定修复后，5 轮实质回答及 1 轮澄清通过 |

[二次 AI 复核](evaluations/conversation-round3/development-secondary-review.md)支持既定评分口径；它看到既有评分，仍属于开发侧复核。最终版适用的检索覆盖 5/5、引用支撑 5/5，错误拒答 0；引文原文存在 25/25、引用对象存在 12/12 是另两项机械指标。最终 6/6 是 **AI 开发侧对已暴露题的回归评分**，不等于独立新题准确率、生产质量或性能提升。仅 1/5 个实质回答正文明确重申 local/synthetic；其余未外推生产，但两种口径不能混用。

### 两个真实 DPO 旧失败的补充检查

[补充记录](evaluations/conversation-round3/targeted-generation/README.md)只测首版共享生成路径，使用原检索父文档：2 个主要旧错误均修正——能够识别 SFT 基线，配置 false 不能证明历史逐步运行行为。4 次调用、65,784 个已知 token。

完整报告严格通过仅 **1/2**：另一份回答将空白分词计数称为 tokens，且选取表格行时没有完整携带列标题。该路径未启用工作区的固定复核命题契约，也没有重新评测检索。最终版更改了片段目录后没有重跑这两题，因此不能将其 2/2 主要错误修正写成最终 Agent 全链路验收。

### 冻结后的新题

[新题完整报告](evaluations/conversation-round3/new-scenarios/REPORT.md)：独立于实现与旧题出题的 AI 冻结了 2 个新场景、6 轮问题和 8 份英文合成资料，采用中文追问；同一冻结候选只运行一次。这仍是 AI 编写、AI 评分的本地合成评测，不是人工独立评测。

**完整报告交付 0/6；其中实际提交 2 轮，均在 `review_started` 后触发 `agent_timeout`，其余 4 轮按预设依赖规则阻塞。** 两次实际首轮均检索到必要证据（2/2），但没有最终答案，所以不能给引用蕴含、错误拒答或后续指代纠正打通过分，也不能称为六个错误答案。

轨迹证明 75 秒预算在开始最终复核后耗尽。现有证据不能区分供应商响应慢、请求大小、调度等具体原因，不能归因于模型能力。两份中间草稿还存在单条漏引测量值、判定标签不一致或未明确汇总等问题；没有完成的复核结果，草稿不计入最终答案成绩。

服务报告 7 次尝试调用：5 次决策返回并有 usage，2 次复核开始后未返回，供应商是否接收及计费未知。已观测 21,113 tokens **只是部分用量**，两任务总用量未知，不能记为 0，也不能与成功运行作完整费用比较。

因此本轮结论是：工程回归与已知问题修复通过，**新场景完整交付未通过**，总体可靠助手验收仍未完成。冻结材料和失败已公开；今后重跑这组题必须作为已暴露回归。

## 后续安排

下一轮优先处理复核阶段的执行预算和可诊断性：

1. 增加模型决策、工具、复核请求的分阶段耗时、剩余预算、请求规模与取消终态记录，先用受控延迟复现预算不足，保留未知用量。
2. 根据测量结果压缩重复上下文、减少不必要往返或调整分阶段预算；不直接放宽总时限来宣称修复，也不把未核验草稿当成最终报告。先用本轮失败题做已暴露回归。
3. 新冻结一组未见问题再验证完整链路；把执行交付、语义正确、引文蕴含和错误拒答分开评分。未见题不用于当轮反复调参。

长期记忆继续顺延。后续若做最小版本，先实现用户明确保存的偏好、作用域、来源与可删除记录；模型结论自动写入需要另外的证据与失效机制。

暂停、检查点续跑、SSE、精确 tokenizer、自动事实摘要和跨会话长期记忆仍未实现。用户固定短期状态与 MySQL 历史持久化已经存在，不能将其改称自动长期记忆。本轮没有修改 Codex 或个人账户的记忆。
