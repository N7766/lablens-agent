# 分析计划与混合结果

在网页切换“分析计划”，可以载入固定离线示例，也可以输入问题后用真实模型生成计划。生成只发一次请求，没有自动修复或重试；失败会明确显示，轨迹可下载。

1. 检查每步引用的问题片段和实际筛选条件、比较方向。
2. 如需修改，展开“高级：编辑计划 JSON”，再点“预览当前计划”。
3. 点击“按此计划执行”，获取逐步表格和原文说明。
4. 下载完整可复核结果，在“离线复核”上传，或运行 `lablens verify result.json`。

网页模型规划只接收问题和内置实验摘要/说明，不读取“条件查询”上传的数据。预览/执行接口支持请求内自定义数据，不调用模型，不修改内置快照。

## 支持的计划

最多6步，依次执行。每步必须有唯一`id`和来自问题的原文片段`request_excerpt`。

- `query`：同条件查询的筛选、排序、top-k、并列和Pareto。最高/最低需要`top_k: 1`；仅排序会返回全体记录。
- `compare`：基线到候选的准确率百分点差、正确题数差、长度减少比例，保留原始单位及比较边界。
- `describe`：展示已有字段、未记录字段和全部方法说明原文，不能替代重新做统计检验或测时。
- `unhandled`：列出无法处理的要求及原因；执行结果为`partial`，不当作完整完成。

比较对象可为`{"run_id":"run:sft"}`，或`{"query_step":"best"}`。后者必须引用前面恰好返回一条记录的查询。空集或并列会阻止预览，需要明确选择，不能默认取第一条。

示例请求：

```json
{
  "question": "找出准确率最高的所有并列记录；以SFT为基线比较该唯一结果。",
  "plan": {
    "steps": [
      {"id":"best","kind":"query","request_excerpt":"找出准确率最高的所有并列记录","query":{"top_k":1}},
      {"id":"delta","kind":"compare","request_excerpt":"以SFT为基线比较该唯一结果","baseline":{"run_id":"run:sft"},"candidate":{"query_step":"best"}}
    ],
    "unhandled": []
  }
}
```

`POST /api/plan/draft`接收`{"question":"…"}`并返回待复核计划及原始模型轨迹。`POST /api/plan/preview`接收上面结构（可加`dataset`），返回`preview_id`。将此ID加入原请求，发给`POST /api/plan/execute`。问题、计划、数据或说明改变均使旧预览失效。

预览阶段会在内存中计算只读步骤，以验证引用、数据口径和可执行性；不提交持久化动作，也不调用模型。点击执行才交付完整结果和receipt。

`POST /api/receipt/verify`与CLI自动识别单查询和多步骤receipt；计划receipt包含问题、标准化计划、数据、每步结果和内容哈希。重算核对布尔值与数值类型，允许浏览器将`1.0`序列化为`1`。

## 工具循环的变化

“Agent分析”仍可自主多轮调用工具。查询之后，不再丢弃已经读到的比较、数据范围或说明；这些内容与查询表一起按工具证据展示。原始模型文字保留在轨迹中。模型如果没调用某一步需要的工具，该部分仍可能遗漏，必须按完整问题审核。

## 不能由此推导的结论

- 原文匹配只检查片段存在，不证明参数正确或请求完整。
- 已执行表示**列出的计划步骤**完成；预览ID只绑定内容，不是身份签名或人工审核证明。
- 资料原文可能包含局限甚至外部错误，系统不自动认证来源真实性。
- receipt复核通过表示所含数据、计划和结果内部可重算；不能证明真实来源、语义正确或统计显著性。
- 仍为本机研究原型，没有会话持久化、生产鉴权或多用户费用控制。
