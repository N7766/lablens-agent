# LabLens 会话第四轮：性能诊断、复核正文去重与后端路线

日期：2026-10-29。源码冻结于 `b737ef7554ed368616f8485b55fed8666f574017`；仍属 v0.13 候选迭代，不是正式发布。本轮完成性能观测与可控故障验证；真实模型的旧失败仍未收敛，不能称为可靠性验收通过。

## 背景与设计

第三轮的两次新题首轮均在复核开始后超时，但旧轨迹无法区分时间花在模型决策、工具还是复核。本轮先补足这一证据缺口，再压缩可以证明重复的内容。Java / Spring Boot 继续负责 MySQL 版本化资料、会话和任务；Redis 继续负责缓存与限流；Python 负责工具循环、检索和模型调用。本轮没有引入 MQ 或新的数据库。

| 改动 | 实际行为 | 边界 |
|---|---|---|
| `runtime-stages-v1` | 决策、工具和复核记录成对起止、父阶段、耗时、剩余预算和终态 | 嵌套阶段有重叠，不能求和；客户端耗时不等于模型纯推理耗时 |
| 请求观测 | 保存实际 HTTP JSON 正文字节、配置网络超时、HTTP 状态及已知/未知 usage | 不保存请求正文、密钥或异常文本；没有流式 TTFT，超时请求是否被上游接收/计费仍可能未知 |
| 紧凑复核 | 完全匹配的草稿引文改用证据 ID，删除重复命题清单和重复当前问题 | 完整原文目录、证据元数据、固定命题 schema、规则与后置检查保留；无法精确映射则回退 |
| Java 持久化 | 接受 `workspace-agent-v5`，白名单保留计时字段，轨迹上限 128 | 未知 token 保持未知；`returned` 不表示语义正确 |
| 界面 | 历史任务可展开“分阶段耗时与预算”，失败记录也能查看 | 未返回的用量明确不能计零；详情用于排障，不认证答案 |

75 秒总预算仍在调用边界检查，最多 6 次模型决策加 1 次复核，没有供应商自动重试。HTTPX 网络超时是网络阶段/空闲等待约束，不是严格端到端抢占式截止；准备、解析和调度可能使观测时间略超预算。不能承诺终止已经发出的上游计算。

## 新冻结题验收

[新题完整报告](evaluations/conversation-round4/new-scenarios/README.md)：独立于实现和旧题的 AI 编写并冻结了 2 个新场景、6 轮中文问题、7 份英文合成资料，运行前/后核对 59 个源码文件；原始输出封存后再由该出题 AI 评分。这不是人工独立评测。

**交付 6/6，严格通过 5/6，无阻塞、无重试。** 其中 4 轮为实质验收回答，1 轮正确说明真实缺失的 peak RSS，1 轮正确澄清“它”指向哪次运行。检索所需证据覆盖 5/5 个适用轮次；有事实主张的引用支撑 5/5；另 1 轮纯澄清无需检索或事实引用，不能称为第六次检索成功。未观察到错误拒答，用户更正与资料版本范围均符合该小题集要求。

## 后续多阶段路线与下一轮

完整 [后端与 LLM 工程能力路线](backend-llm-capability-roadmap.md)按业务场景、依赖、负面测试、资源上限和证据安排为 8 个阶段：性能诊断 → RabbitMQ/outbox/inbox → 鉴权、准入与背压 → 十万/百万任务元数据与查询优化 → 故障演练和真实试用 → 记忆与检查点 → 冻结语义评测 → GPU 私有部署及模型压测。每阶段可分多轮，已有组件与计划组件严格区分。

**下一轮先收敛本次超时暴露的执行路径，再推进 MQ。** 用已暴露资料验证重复读取是否可避免、完整原文是否在多步消息中重复累积、可否缩短带大草稿的决策路径；每次改动保留证据覆盖、最终复核和同条件回归。另预声明模型/输出上限、样本与费用，做有界调用时延对照。新题一旦出分即归入后续回归，不用于当轮反复调参。不能跳过核验或单纯放宽总时限来宣称优化。

MQ 的首个落地场景是批量导入/索引及任务就绪通知，MySQL 仍作权威状态；事件重复投递不能触发未知 LLM 调用自动重放。后续规模实验分别测任务元数据、资料文本与向量索引，不把百万行数据说成百万真实用户。公网试用前需补身份、权限和全局付费额度。

用户已确认可租 GPU 且有资金预算。GPU 阶段先确定最高费用、时长、自动关机与存储计费，再选 Linux NVIDIA 单卡和模型。本轮未租 GPU，也未私有部署模型。模型压测将单列 TTFT、TPOT、token/s、显存、并发和费用，与后端吞吐及 Agent 答案质量分开。
