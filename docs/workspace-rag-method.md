# 持久工作区的文档 RAG：冻结语料、指标与复现

这套评测使用真实项目的已有公开文档，比较 BM25、真实模型向量检索与混合检索。它验证一个受限研究工作台的检索与引用链路；不把引入组件本身当成效果提升，也不把本机测试称为生产运行。

## 数据与预声明

[`evaluation/workspace/corpus.json`](../evaluation/workspace/corpus.json)包含 27 份文档、14,496 个正文字符：6 条 LabLens 已有方法说明、13 段 DPO 项目报告、8 段 LabLens 版本文档。正文为已有 Git 提交中原文摘录，标题由实现助手整理。每份记录保存原仓库、提交、相对路径、章节或 JSON ID、完整源文件 SHA-256 和正文 SHA-256。公开文件不含本机绝对路径、密钥、个人简历或整批历史评测轨迹。

这两个仓库描述同一个作者的 DPO 实验及其分析工具，**不构成第二个独立真实实验项目**。训练报告是历史记录，没有在本轮重新训练或测量。旧报告把部分空格分词数写成 tokens，应结合 `note:units`、`dpo:limitations` 阅读。旧版本能力和最终评测计划保留历史作用范围，计划不等于已完成实验。

[`queries.json`](../evaluation/workspace/queries.json)的 24 道题在第一次检索、嵌入或生成调用前固定，开发集 8 题，保留集 16 题；合计 18 道可回答题、6 道无答案题。包含字面查询、改写、中英文跨语言表达、多文档问题、领域外问题及看起来相关但缺少实测值的问题。题目、所需文档 ID 和回答边界均事先写定。开发和保留分数分开统计。

题目和标签由读过语料、了解实现目标的同一助手编写。这里的保留集仅表示本轮实现时没有先运行这些问题，**不代表独立作者、独立人工、盲审或外部标准基准**。不能根据失败结果修改标签并覆盖原分数。

[`manifest.json`](../evaluation/workspace/manifest.json)记录冻结时间和文件哈希。评测器每次执行前核对这些哈希。源文件可从指定 Git 提交重新提取：

```bash
python evaluation/workspace/build_corpus.py --dpo-repository /path/to/dpo-cot-compression --output /tmp/rebuilt-corpus.json
```

## 实际调用与费用边界

[`scripts/evaluate_workspace_rag.py`](../scripts/evaluate_workspace_rag.py)调用正在运行的 `POST /api/rag/answer`，不调用模拟响应，不生成假向量，不对失败自动重试，也不隐藏预热或补抽样。默认依次执行 BM25、dense、hybrid，每组依照冻结顺序；每次请求最多取 5 个片段。

```bash
# 全部 24 题 × 3 策略，生成模式为原文摘录。
# BM25 本机执行；dense/hybrid 会实际请求配置的 embedding 服务并产生费用。
python scripts/evaluate_workspace_rag.py \
  --endpoint http://127.0.0.1:8765/api/rag/answer \
  --output reports/workspace-rag-retrieval

# 预先固定 h01、h04、h08、h15 四题，只测 hybrid，最多四次真实生成。
python scripts/evaluate_workspace_rag.py \
  --endpoint http://127.0.0.1:8765/api/rag/answer \
  --strategies hybrid --live-generation --live-limit 4 \
  --output reports/workspace-rag-live
```

未配置或不可用的向量服务必须保留 `unavailable` / `provider_error`，不得拿 BM25 或随机向量充当 dense 的结果。失败请求保留原状态和 HTTP 状态，退出码为 2；输出目录已经存在结果时拒绝覆盖。

文档向量使用服务进程内缓存。当前问题向量每次调用重新请求提供方。因此 24 题的 dense 和 hybrid 共最多 48 次问题嵌入请求，另加初次语料分批嵌入；四题真实生成另外增加四次问题嵌入和最多四次生成。实际计数以返回用量为准，服务失败或没有报告 token 时保留未知，不能按零费用理解。

## 指标定义

- **文档 Recall@5**：前 5 个检索片段涵盖的所需文档数 / 该题所需文档数。多个片段属于同一文档只记一次，不继续取后面片段补满五份文档。分母包含全部可回答题；失败或不可用请求按 0 记录，同时单列可用请求数。标签是有限的必需证据，不能保证穷尽所有语义相关文档。
- **MRR@5**：前 5 个片段中第一次命中所需文档的排名倒数；未命中为 0。它不验证多文档问题是否覆盖全部证据，因此另报“所有所需文档均召回”的题数。
- **引用来源一致性**：核对引用 ID 是否在检索结果、文档 ID 与来源标题是否一致、字符偏移是否对应原文、原文 SHA-256 是否一致。没有引用的请求不进入引用条目分母。该指标**不是语义忠实度或答案正确率**；合法引用可以被错误解读。
- **无答案处理**：单列 6 道题，`refused` 或 `no_hits` 记作拒答，服务异常不算成功拒答。可回答题上的拒答也单独计数。纯摘录模式没有校准的可回答性判断；返回相关片段记作未拒答，但不能据此称为模型编造事实。
- **延迟和用量**：记录客户端端到端时间、服务端检索时间、p50/p95、生成调用数、嵌入请求数、输入数、文档缓存命中、已报告 token 与未知用量。p95 用线性插值，小样本只描述这次运行，不外推线上 SLA。失败请求也保留在时间分布中。

**延迟不能直接用于宣称 hybrid 比 dense 快。** 首次 dense 请求可能承担整个文档嵌入，后续 dense/hybrid 共用文档缓存；问题嵌入仍有外部网络时间。报告按 `document_cold_or_partial_query_uncached` 与 `documents_cached_query_uncached` 分组，策略执行顺序和缓存条件全部保留。本轮不是隔离硬件、随机化顺序的速度对照。

纯摘录检索评测与四题真实回答分开。真实回答只检查拒答状态与来源一致性，不自动使用另一个模型打分，不汇总未经人工语义审核的“答案正确率”。

## 结果与错误分析要求

每次运行保存 `results.jsonl`（逐请求立即写入）、`summary.json`（响应、原文证据、分组指标、失败清单、运行前后实现哈希）和 `report.md`。默认在忽略提交的 `reports/` 下。后续公开汇总应指向具体运行，保留所有失败，不单取最好一次。

解释结果时至少区分：未检索到关键文档、跨文档证据不齐、无答案题只返回相关内容、生成拒绝、生成结构/引用被拒绝、提供方不可用与请求超时。若正式运行期间实现文件改变，应重新界定该次结果的适用实现，不能把混合版本统计当成一个冻结版本。

这一小语料可作为端到端测试和初始基线；需要新的真实资料、他人编写的问题和独立语义复核，才能判断实际研究使用价值。向量召回没有改善也应照实保留，之后依据漏检类别决定是否调整切块、检索或语料。
