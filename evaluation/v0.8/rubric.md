# v0.8 跨快照契约检查

这 6 道题和全部数值预期在模型调用前固定。A/B 使用相同的记录 ID 与问题，
但数值、名次、边界并列和 Pareto 成员不同；C 使用独立的合成 token 数据。
这些输入均为人工设计的工程样例，不是模型训练或实验测量结果。

每次运行使用独立请求上下文，不是对话记忆基准。默认命令仅执行预先写好的
参考计划，零模型调用。`--live` 才调用真实模型，每题最多两次请求；提供方错误
不会触发额外重试。失败会原样保留，不选择性重跑。

自动契约检查必须同时满足：

1. 轨迹、输入数据、预览、执行收据和每张查询表均对应本题快照。
2. 所有预声明步骤都存在，无额外或未处理步骤。查询条件、排序、截断、并列
   参数符合契约；即使结果碰巧为空，也必须检查条件和 `top_k`。
3. 查询成员与固定预期相同；排序题检查顺序，不指定顺序的全集/Pareto 题只检查
   成员。结果中的完整记录必须与当前快照相同，同 ID 的旧值不能通过。
4. 比较必须使用指定基线和候选，检查正确题数差、准确率百分点差和长度减少比例。
5. describe 必须包含当前快照全部原文说明、单位/来源/合成标志字段和预声明缺失字段。

收据重算结果单独报告。它只能证明已列步骤可复算，不证明计划覆盖自然语言。
`contract_pass` 只表示通过这份明确的自动契约，不是独立人工审核、一般语义正确率、
真实实验表现或统计显著的模型提升。参考计划也是工程检查，不能算作模型成功。

数据的 `source_sha256` 对应同目录下明确说明合成数值的 source JSON 字节，仅用于
追溯输入来源；它不是实验真实性认证。tokenizer 是合成计数约定，不表示运行过真实分词器。
